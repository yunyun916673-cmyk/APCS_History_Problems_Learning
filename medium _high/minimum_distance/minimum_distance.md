# 最短路徑數量

## 題目敘述

有 N 個城市，編號為 1 到 N，以及 M 條雙向道路。每條道路皆需要 1 小時才能通過。

請計算從城市 1 到城市 N 的所有路徑中，所需時間最短的路徑數量。

由於答案可能很大，請將答案對 1000000007 取模後輸出。

如果無法從城市 1 抵達城市 N，請輸出 0。

限制

2 ≤ N ≤ 2 × 10⁵

0 ≤ M ≤ 2 × 10⁵

1 ≤ Ai < Bi ≤ N

任意兩條道路的端點組合皆不相同。

所有輸入值皆為整數。


## 輸入格式



N M  
A1 B1  
A2 B2  
⋮  
AM BM

第 i 條道路連接城市 Ai 和 Bi，通過該道路需要 1 小時。

## 輸出格式

輸出一個整數，表示從城市 1 到城市 N 的最短路徑數量對 1000000007 取模後的結果。

若城市 1 無法抵達城市 N，輸出 0。

# 最短路徑數量

## 題目想法

一開始看到這一題的時候，我發現這一題需要維護兩個東西，一個是從起點到每個點的最短路徑，另一個是總共有多少種方式可以用最短路徑到達這個點。

如果我要同時維護這兩種資訊，感覺會比較麻煩，所以我就開始想，有沒有什麼方法可以利用題目本身的特性，讓我不需要一直額外計算最短距離。

後來我想到 BFS。

因為 BFS 本身就是分層搜尋，所以我可以利用它的分層結構來處理這一題。當 BFS 第一次走到一個點時，代表目前找到的就是到達這個點的最短路徑。

因此，對於同一個點，我只需要去看有多少個同一層的 BFS 節點可以到達它，就能知道總共有多少種方式可以用最短路徑到達這個點。

這樣就可以利用 BFS 的特性，同時處理最短路徑以及最短路徑數量。

## 解題過程

根據題目的要求，我先建立 mod 函式，讓之後計算路徑數量時可以直接對 1000000007 取模。

接著建立 n、m，並使用 ship 儲存每個節點之間的道路關係。

另外建立 dp，讓 dp[x] 表示目前總共有多少種最短方式可以到達 x。

我也使用 dist 記錄從起點到每個點的最短距離。

一開始把 dp[0] 設成 1，代表從起點到自己有一種方式，並把起點放進 BFS 的 queue 中。

在 BFS 裡面，每次從一個點走到另一個點時，我會判斷：

level + 1 是否小於等於 dist[nxt]。

這裡可以分成兩種情況。

第一種是小於。

因為我使用的是 BFS，所以正常情況下不會出現已經找到一個較短距離之後，又從後面的 BFS 層找到更短距離的情況。

這裡的第一次小於，實際上就是第一次走到這個點。

第一次走到這個點時，我就把 dist[nxt] 更新成目前的距離，並且把 dp[pwd] 加到 dp[nxt]，然後把 nxt 放進 temp 裡面，讓它之後可以繼續進行 BFS。

第二種是等於。

這代表目前又有一個同樣層數的 BFS 節點可以到達 nxt。

因為兩個節點在同一層，所以它們到 nxt 的距離也相同，也就是說，我又找到了一條同樣長度的最短路徑。

因此這時候只需要把 dp[pwd] 加到 dp[nxt]，不用再把 nxt 放進 temp。

因為 nxt 之前就已經被放進 queue 了，之後還是會被處理。如果再次放進去，反而會讓同一個節點被重複處理，造成不必要的計算。

至於大於的情況，我就不需要處理。

因為代表現在是用比已知最短路徑更長的方式到達這個點，而題目只要求最短路徑，所以這種路徑不需要加入 dp。

最後在 main 中完成初始化後執行一次 BFS，全部搜尋完成後，dp[n-1] 就是從城市 1 到城市 N 的最短路徑數量。

## 解題方法思考

這一題讓我比較有印象的是，我在寫完程式之後，曾經想過 dist 能不能刪掉。

一開始我覺得 dist 好像只是在當 visited 使用，因為 BFS 第一次走到一個點時，就已經是最短距離，所以我曾經想把 dist 改成 visited。

但是實際思考之後，我發現 visited 其實沒有辦法完全取代 dist。

dist 在這份程式裡面其實有兩個作用。

第一個作用和 visited 很像，可以記錄這個點之前有沒有被 BFS 到達過。

但第二個作用是 visited 沒有辦法做到的，那就是分辨目前到達這個點的方式，是不是和之前一樣都是最短距離。

因為這題要求的是最短路徑，所以只有在同一層，也就是使用相同步數到達這個點的路徑，才能被加入 dp。

如果使用更長的路徑到達這個點，就不能更新 dp，因為那已經不是題目要求的最短路徑。

如果只使用 visited，我只能知道這個點有沒有到過，卻不知道目前到達它的節點是不是和原本的最短距離在同一層。

如果真的要只使用 visited，就需要再增加其他結構來記錄層數，這樣反而會讓程式變得更複雜。

所以最後我還是保留 dist。

這次修改的過程也讓我發現，一個變數看起來可能和另一個變數功能很像，但實際分析之後，才會發現它們保存的資訊並不完全相同。

## 複雜度分析

### 時間複雜度：

O(N + M)

因為使用 BFS，每個城市最多被加入 queue 一次，而每條道路最多會從兩個端點各檢查一次，所以整體時間複雜度為 O(N + M)。

### 空間複雜度：

O(N + M)

ship 需要儲存所有城市之間的道路，總共需要 O(N + M) 的空間，而 dp、dist 和 BFS 的 queue 最多也需要 O(N) 的空間，所以整體空間複雜度為 O(N + M)。

## 學習心得

這一題讓我更加理解 BFS 的分層特性。

以前我比較常把 BFS 當成一種用來找最短路徑的演算法，但這次我發現 BFS 不只是可以找到最短路徑，也可以利用它一層一層搜尋的特性，進一步去計算最短路徑到底有多少種。

而且這題也讓我實際體會到，當我覺得某個變數好像可以刪掉的時候，不能只看它表面上的功能，而是要真的去分析它到底維護了哪些資訊。

我原本以為 dist 只是用來當 visited，所以嘗試把它改掉，但後來才發現 dist 還可以用來判斷兩次到達同一個點的距離是否相同。

這也讓我對 BFS 中的層數有了更深的理解。以前我只知道同一層代表距離相同，但這次我真正把這個特性拿來做路徑數量的計算，也讓我知道如何利用已經學會的演算法去維護更多資訊。
