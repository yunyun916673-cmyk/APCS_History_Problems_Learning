# 蓋步道

## 題目意思

有一個 (n\times n) 的方形區域，每個格子都有一個海拔高度。需要從左上角 ((1,1)) 鋪設一條步道到右下角 ((n,n))，步道只能沿著區域內格子的上下左右方向移動。

一條步道會經過許多格子，而相鄰兩個格子的海拔高度可能不同。希望選擇一條路徑，使整條路徑中相鄰格子的最大高度差盡可能小。

需要輸出：

1. 所有可行路徑中，最大高度差的最小值。


2. 在這個最小最大高度差的條件下，從左上角走到右下角所需的最短路徑長度。

## 輸入格式

第一行輸入一個整數 (n)，代表方形區域的大小。

接下來有 (n) 行，每行包含 (n) 個正整數 (h_{ij})，代表座標 ((i,j)) 的格子海拔高度。

## 輸出格式

輸出兩行：

第一行輸出所有可行步道中，最大高度差的最小值。

第二行輸出在達到上述最小最大高度差的情況下，從左上角走到右下角的最短路徑長度。

## 題目範圍

(1<= n <= 300)

(1 <= h_{ij} <= 10^6)


# 蓋步道

## 題目想法

一開始我看到這一道題目的時候，還有點不知所措，因為這一題它要求的同時有兩個東西，一個是最小的高度差，另一個是在這個條件下的最短路徑。

但是我重新再看一遍題目的要求之後，發現這其實很像二分搜尋。因為我可以先搜尋一個高度差，然後判斷在這個高度差的限制下，是否能找到一條從起點走到終點的路徑。

如果可以走到終點，就代表這個高度差可能還可以再更小，所以往左邊繼續搜尋；如果不能走到終點，就代表高度差還不夠，需要往右邊搜尋。

而在判斷一個高度差能不能走到終點的部分，就可以使用 BFS。

所以最後就變成二分搜尋加上 BFS，就可以解決這一題。

## 解題過程

在 `check` 函式裡面，它的參數就是目前所能接受的最大高度差。

我會先從左上角開始做 BFS，在 BFS 過程中，如果目前走到的格子和下一個格子的高度差大於 `ove`，就代表這一步不能走，所以直接跳過。

如果高度差沒有超過 `ove`，就可以把這個格子加入 BFS 的佇列中，繼續往其他地方搜尋。

最後如果可以走到右下角，就代表目前這個高度差是可以接受的，同時因為使用 BFS，所以找到終點時得到的路徑長度也是目前這個高度差限制下的最短路徑。

另外，如果 `n` 等於 1，代表起點和終點本來就是同一個格子，所以直接回傳 0。

主要的部分還是在 `main` 裡面。

在初始化完成之後，我直接進行一次二分搜尋，每次取一個可能的最大高度差，呼叫 `check` 判斷能不能走到終點。

如果可以，就把答案記錄下來，然後把搜尋範圍往更小的高度差縮小；如果不能，就把搜尋範圍往更大的高度差移動。

最後就可以得到所有可行路徑中，最大的相鄰高度差最小是多少，以及在這個高度差限制下的最短路徑長度。

## 解題方法思考

這一題一開始看起來需要同時處理高度差和路徑長度，所以我一開始其實不太確定應該怎麼做。

但重新看題目之後，我發現真正需要先解決的是「最小的最大高度差」。

所以我沒有直接去找最佳路徑，而是先固定一個高度差，然後利用 BFS 判斷在這個限制下能不能走到終點。

這樣就可以把原本的問題轉換成一個可以判斷的問題。

而且這個判斷具有單調性，如果某個高度差可以走到終點，那麼比它更大的高度差也一定可以走到終點，因此就可以使用二分搜尋找出最小的可行高度差。

找到這個最小高度差之後，`check` 裡面的 BFS 本身就可以取得這個條件下的最短路徑長度。

所以最後使用二分搜尋搭配 BFS，就可以同時處理題目要求的兩個答案。

## 複雜度分析

時間複雜度：

O(n² log 10⁶)

每一次 `check` 都會使用 BFS，最多走過 n² 個格子，所以一次是 O(n²)。

而二分搜尋最多需要 O(log 10⁶) 次，因此總時間複雜度為 O(n² log 10⁶)。

空間複雜度：

O(n²)

主要需要使用 `grid`、`visited` 以及 BFS 的 queue，因此空間複雜度為 O(n²)。

## 學習心得

這一題讓我比較明顯感受到，有時候題目同時要求很多東西時，不一定要直接想辦法一次把所有東西處理掉。

一開始我看到最小高度差和最短路徑同時出現的時候，會覺得兩個條件混在一起很難處理。

但重新分析之後，我發現可以先固定一個高度差，再去判斷這個高度差到底能不能走到終點，這樣問題就簡單很多。

這也讓我更熟悉二分搜尋不只是拿來搜尋一個數字，也可以拿來搜尋一個答案，搭配 BFS 之後就能解決這種最小化問題。
