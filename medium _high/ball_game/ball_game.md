# 球球遊戲

## 題目意思

桌上有 \(N\) 顆球，球的位置從 \(1\) 到 \(N\) 編號。每顆球都有一個數字，初始時第 \(i\) 個位置上的球記錄數字 \(i\)。

接下來進行 \(M\) 次操作：

1 a b：交換位置 \(a\) 與位置 \(b\) 上的球。

2 c：取得目前位置 \(c\) 上球的數字，並將其加入總和。


請依序完成所有操作，最後輸出取得的數字總和。

## 輸入格式

第一行輸入兩個整數 \(N,M\)，分別表示球的數量與操作次數。

接下來 \(M\) 行，每行輸入一個操作：

1 a b

2 c


## 輸出格式

輸出一個整數，表示所有 2 c 操作取得的數字總和。

## 範圍限制

\(2 <= N <= 10^9\)

\(1<= M <= 10^5\)

\(1 <= a,b,c <= N\)

\(a != b\)

# 球球遊戲

## 題目想法

原本看到這一題的時候，我的第一個想法是直接使用 vector，把每一個球目前的位置存下來。

但是後來看到 N 最大會到 10^9，發現如果真的開一個大小為 N 的 vector，空間一定會太大，所以不能直接把所有東西都存下來。

後來我就想說能不能改用 unordered_map，畢竟 unordered_map 底層是雜湊表，可以只存需要的資料，不需要像 vector 一樣一次開出整個空間。

不過後來我才發現，這一題真正的關鍵其實不是單純把 vector 換成 unordered_map，而是根本不需要把所有球的位置都存下來。

因為如果某一個位置從來沒有被做過任何動作，那它就一定還是原本的球，也就是它的編號加上 1。

所以我只需要把有被操作過的位置記錄下來，沒有被記錄的位置就直接當成原本的位置處理，這樣就可以避開 N 太大的問題。

## 解題過程

我使用 unordered_map temp 來記錄有被操作過的位置。

首先我寫了一個 getting 函式，用來取得某個位置目前的球編號。

如果這個位置已經存在於 temp 裡面，就代表它之前被操作過，所以直接回傳 temp 裡面目前記錄的結果。

如果這個位置沒有被記錄，就代表它從頭到尾都沒有被改變，因此它還是原本的球，只要直接回傳位置編號加 1 就可以了。

接著我寫了一個 moving 函式來處理交換。

在 moving 裡面，我先使用 getting 分別取得 A 和 B 目前所放的球，再把這兩個結果交換後放進 temp 裡面。

這樣就算 A 或 B 之前已經被交換過，也可以透過 getting 取得它們現在真正的球，而不是只看它們原本的編號。

最後在 main 裡面，我就依照題目的操作種類進行處理。

如果是交換操作，就呼叫 moving 來交換 A 和 B。

如果是詢問操作，就直接使用 getting 找出目前這個位置上的球，再把結果加到 ans 裡面。

## 解題方法思考

這一題本身的操作其實很簡單，真正困難的地方是 N 實在太大。

一開始我想直接使用 vector，但因為 N 最大可以到 10^9，所以這個方法在空間上不可行。

後來我想到使用 unordered_map，希望只存實際需要的資料。但真正讓我解決這一題的關鍵，是後來發現沒有被操作過的位置根本不需要額外儲存。

因為只要一個位置沒有被操作過，就可以直接知道它目前還是自己的編號加 1。

所以最後我只需要儲存曾經被操作過的位置，就可以在不開出 N 大小陣列的情況下完成所有操作。

這讓我發現，當題目的資料範圍非常大的時候，不一定要想辦法把整個資料結構存下來，有時候可以反過來思考哪些資料其實根本不需要儲存。

## 複雜度分析

### 時間複雜度：

O(m)

每一次操作只需要進行常數次 unordered_map 的查詢或修改，因此平均可以在 O(1) 完成。

### 空間複雜度：

O(m)

因為最多只會記錄曾經被操作過的位置，而總操作次數最多為 m，所以不需要配置 N 大小的空間。

## 學習心得

這一題其實不算困難，但是因為 N 實在太大，所以不能直接使用最直覺的方法。

我原本一直在想要怎麼把 vector 換成其他資料結構，後來才發現真正需要改變的是我的思考方式，而不是單純換一個容器。

這題讓我學到，遇到資料範圍非常大的題目時，可以先想想看是不是有一些資料其實不需要真的存下來。

這次我就是利用「沒有被操作過的位置一定還是原本的球」這個特性，只記錄真正有改變的部分，最後才能成功在很大的 N 下完成這一題。

我覺得這也是這題最值得學習的地方：當原本的方法因為資料範圍太大而無法使用時，需要轉換思路，而不是一直想辦法硬套原本的方法。
