# 市區導航路線規畫

## 題目意思

城市的道路地圖是一個 M × N 的笛卡爾二維直角座標系方格圖，每個方格以 (x, y) 表示，其中：

x 軸由西向東增加。

y 軸由南向北增加。

起點固定為 (0, 0)。

車輛只能向東或向北行駛，每次移動一格，不能斜走，也不能後退。

部分方格為不可行駛區域，車輛不能進入。

部分方格禁止左轉；從任何方向抵達這些方格時，都不能在該方格進行左轉。

給定目的地座標後，求從 (0, 0) 到目的地的最短行車路線長度。


## 輸入格式

第一行輸入兩個正整數 M、N，分別表示地圖在東西方向與南北方向上的方格數。

第二行輸入兩個非負整數 P、Q，分別表示不可行駛方格的數量，以及禁止左轉方格的數量。

第三行輸入兩個非負整數，表示目的地方格的東西向座標 x 與南北向座標 y。

接下來 P 行，每行輸入兩個非負整數 x、y，表示一個不可行駛方格的座標。

接下來 Q 行，每行輸入兩個非負整數 x、y，表示一個禁止左轉方格的座標。

所有座標皆使用笛卡爾二維直角坐標系表示。

## 輸出格式

輸出從起點 (0, 0) 到指定目的地的最短行車路線長度。

測資範圍

1 <= M <= 500

1 <= N <= 500

0 <= P + Q <= M * N / 2 - 2

所有出現的座標 (x, y) 皆滿足：

0 <= x < M

0 <= y < N

# 市區導航路線規畫

## 題目想法

一開始看到這一題的時候，我發現它和一般的 BFS 有一個比較不一樣的地方，就是有些格子不能夠左轉。

因此，如果只記錄目前所在的 X、Y 位置是不夠的，因為到了同一個格子時，如果是從不同方向過來，接下來能不能左轉的情況也會不一樣。

所以這裡就需要知道它原本是從哪一個方向過來的，才能判斷下一步什麼時候代表左轉。

因此我最後將 BFS 的狀態開成三個維度，前兩個分別是 X 和 Y，最後一個則是目前的方向，也就是：

visited[x][y][direction]

另外，這一題使用的是笛卡爾座標，而不是一般矩陣常用的 ROW、COL，因此在設定四個移動方向時，也需要針對座標方向做一些調整。

## 解題過程

我在初始化完畢之後，先記錄每一個格子的狀態，分別判斷它是普通的空格、不能行走的牆壁，還是不能左轉的位置。

接著就直接使用 BFS，從起始點 (0,0) 開始進行廣度優先搜尋。

因為 BFS 的狀態除了目前的位置之外，還包含了目前行進的方向，所以在搜尋下一個位置時，就可以利用目前的方向判斷下一步是不是左轉。

如果目前這一格是不能左轉的位置，而下一步的方向又代表左轉，就直接 continue，不讓這個狀態繼續往那個方向走。

另外，因為同一個 X、Y 位置從不同方向進入時，可能會有不同的走法，所以 visited 也需要記錄方向，避免錯誤地把不同狀態當成同一個狀態。

當 BFS 搜尋到終點時，因為 BFS 是按照距離由近到遠進行廣度優先搜尋，所以第一次走到終點時，就一定是最短路徑，這時直接輸出路徑長度即可。

## 解題方法思考

這一題最主要的地方就是不能只把 X、Y 當成 BFS 的狀態。

如果只記錄目前在哪一個格子，那麼當我從不同方向進入同一個格子時，就無法判斷下一步是否為左轉。

所以我將狀態增加成 X、Y 和方向三個資訊，讓程式可以知道目前的位置以及我是從哪個方向過來的。

這樣在遇到不能左轉的格子時，就可以根據目前的方向判斷下一步能不能走。

最後使用 BFS 的原因則是因為每移動一格的成本都相同，所以 BFS 可以保證第一次到達終點時，就是最短的行車路線。

## 複雜度分析

### 時間複雜度：

O(MN)

每一個格子最多有 4 種不同的方向狀態，因此總狀態數最多為 4MN，而每個狀態最多檢查 4 個方向，所以整體仍然是 O(MN)。

### 空間複雜度：

O(MN)

需要使用 grid 儲存地圖狀態，以及三維的 visited 記錄每個位置從不同方向抵達的狀態，BFS 的 queue 也最多儲存 O(MN) 個狀態。

## 學習心得

這一題讓我比較理解 BFS 的狀態不一定只有目前所在的位置。

一開始如果只想到一般的 BFS，很容易會直接使用 X、Y 來判斷一個位置有沒有走過，但是這題因為多了不能左轉的限制，所以我必須把方向也一起考慮進去。

我也注意到這一題使用的是笛卡爾座標，而不是平常矩陣的 ROW、COL，所以在處理方向時需要特別注意，不然很容易把左轉、右轉的方向判斷反。

這題讓我學到，在遇到 BFS 題目的時候，不能只看目前的位置，有時候還需要把會影響後續選擇的資訊一起放進狀態裡。這也是我在這題比較重要的一個收穫。
