# 連接穀倉

## 題目意思

有 N 個田地，田地之間已經存在一些雙向道路。田地 1 和田地 N 分別設有兩個穀倉。

你可以額外興建最多兩條道路，使田地 1 與田地 N 之間可以互相到達。若在田地 i 與田地 j 之間興建道路，成本為 (i-j)^2。

請求出讓兩個穀倉連通所需的最小總成本。

## 輸入格式

第一行輸入 T，代表測試資料的數量。

每組測試資料：

第一行輸入 N、M，分別表示田地數量與既有道路數量。

接下來 M 行，每行輸入 i、j，表示田地 i 與田地 j 之間有一條雙向道路。


## 輸出格式

輸出 T 行。

每行輸出對應測試資料中，使田地 1 與田地 N 連通所需的最小建路成本。

範圍與限制

1 ≤ T ≤ 20

1 ≤ N ≤ 10^5

0 ≤ M ≤ 10^5

任意兩個田地之間最多只有一條道路。

所有測試資料的 N+M 總和不超過 5×10^5。

最多只能新建兩條道路。

建造田地 i 與田地 j 之間的道路，成本為 (i-j)^2。

# 連接穀倉

## 題目想法

一開始看到這一題的時候，我覺得如果要用比較傳統的方法來做會比較麻煩，因為我必須先找出哪些田地屬於同一個連通塊。

找到之後，我需要知道田地 1 所在的連通塊，以及田地 N 所在的連通塊，接著去比較兩種情況。

第一種是直接在田地 1 的連通塊和田地 N 的連通塊之間建立一條道路。

第二種則是經過某一個第三方的連通塊，分別建立兩條道路，先從田地 1 的連通塊連到這個第三方連通塊，再從第三方連通塊連到田地 N 的連通塊。

因為第三方連通塊可能有很多個，所以我還需要不斷比較每一個連通塊所需要的成本，找出最後的最小值。

後來我去查了資料，才發現這一題有一個很適合的處理方式，而且這也是我以前沒有想過的思路，就是雙指標。

## 解題過程

我先利用 DFS 找出田地 1 所在的連通塊，以及田地 N 所在的連通塊。

如果在搜尋田地 1 的時候，就已經可以找到田地 N，代表兩個穀倉原本就已經連通，所以答案直接是 0。

接著我把田地 1 的連通塊與田地 N 的連通塊中的所有田地編號分別存起來並排序。

假設現在有兩個已經排序好的陣列，我在兩個陣列中各放一個指標。

每次先比較兩個指標所指向的田地編號，計算它們之間的距離平方。

因為我要求的是最小成本，所以如果左邊的編號比較小，就把左邊的指標往後移；反過來，如果右邊的編號比較小，就把右邊的指標往後移。

這樣就可以在線性時間內找到兩個連通塊之間建立一條道路所需要的最小成本。

這個方法最重要的地方，就是可以直接排除掉一些不可能成為答案的組合，而不用把兩個連通塊中的每一個田地全部互相比較。

例如現在左邊指標的編號比右邊大，那麼右邊指標往後移還有可能讓兩者的差距變小，所以可以繼續移動右邊指標。

但如果右邊已經沒有可以繼續移動的位置，而左邊的編號又比右邊大，那麼左邊指標繼續往後移之後，編號只會越來越大。

這樣兩個編號之間的差距只會越來越大。

因為我要求的是最小值，所以後面的組合就不可能得到更好的答案，因此可以直接停止，而不用把所有組合都比較一次。

找到田地 1 的連通塊和田地 N 的連通塊直接建立一條道路的最小成本之後，我再處理其他的連通塊。

對於每一個第三方連通塊，我先找出這個連通塊中的所有田地編號並排序。

接著使用剛才的雙指標方法，分別計算：

田地 1 的連通塊到這個第三方連通塊的最小成本。

以及這個第三方連通塊到田地 N 的連通塊的最小成本。

最後把這兩個成本加起來，再拿來更新目前的答案。

因此最後要比較的就是：

直接連接田地 1 的連通塊和田地 N 的連通塊所需要的成本。

以及經過每一個第三方連通塊，建立兩條道路所需要的總成本。

取其中最小的結果，就是答案。

在程式碼中的 TRY 函式裡，我先找出田地 1 和田地 N 所在的連通塊，再使用雙指標求出兩個連通塊直接連接的最小成本。

之後再逐一處理其他連通塊，分別計算它與田地 1 的連通塊，以及它與田地 N 的連通塊之間的最小成本，最後將兩個成本相加並更新答案。

主函式則負責讀入測資、建立道路的圖，最後直接輸出 TRY 所得到的答案。

## 解題方法思考

這一題讓我第一次比較完整地理解雙指標可以怎麼拿來處理兩個集合之間的比較。

如果直接暴力枚舉兩個連通塊中的所有田地，那麼每兩個田地都要比較一次，當連通塊很大的時候，會產生非常多沒有必要的比較。

排序之後，我就可以利用兩個指標的移動，把一些不可能成為最小值的組合直接排除掉。

這樣就不用把所有資訊都處理一次，而是只保留還有可能產生更好答案的資訊。

我覺得這也是雙指標很重要的一個想法，不只是單純讓兩個指標一起移動，而是利用資料已經排序的特性，判斷哪些資訊已經沒有繼續處理的必要。

這一題也讓我開闊了思路，原來兩個集合之間如果要求最小的差距，不一定要把所有組合都拿出來比較，也可以先排序，再利用雙指標有效率地找答案。

這題是求最小化的情況，所以我會從小到大的順序進行處理。如果遇到其他需要最大化的問題，也可以思考是否能利用相反方向的排序與指標移動來減少比較。

## 複雜度分析

### 時間複雜度：

O(N log N + M)

首先使用 DFS 找出所有連通塊需要 O(N + M)。

接著每個連通塊分別排序，所有排序的總複雜度可以控制在 O(N log N)。

排序完成後，雙指標只會讓每個指標往前移動，因此所有雙指標比較的總成本是線性的。

所以整體時間複雜度為 O(N log N + M)。

### 空間複雜度：

O(N + M)

需要使用鄰接串列儲存 M 條道路，同時還需要儲存每個連通塊中的田地編號，以及 DFS 所需要的陣列與 stack，因此空間複雜度為 O(N + M)。

## 學習心得

我覺得這一題最大的收穫不是連通塊本身，而是讓我第一次真正注意到雙指標可以拿來處理兩個集合之間的比較。

以前遇到這種要找最小值的問題，我比較容易直接想到把所有可能的情況都比較一次，但是這樣很容易造成時間複雜度太高。

這次查資料之後，我才發現如果先把資料排序，就可以利用兩個指標的移動來排除掉不可能成為答案的資訊。

這讓我了解到，很多時候要讓程式變快，不一定是想一個完全不同的演算法，也可以先觀察哪些資訊其實沒有必要繼續處理。

這一題也讓我對雙指標有了第一次比較完整的理解。以後如果遇到兩個已排序的集合之間，要找最小差距或其他可以利用單調性的比較，我就會開始想到雙指標，而不是直接暴力枚舉所有組合。
