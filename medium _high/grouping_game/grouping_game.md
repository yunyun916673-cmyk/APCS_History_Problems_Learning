# 分組遊戲

## 題目敘述

有 n 個物品，編號為 1 到 n。每一對物品之間都有一個距離 D[i][j]，距離矩陣滿足 D[i][i] = 0 且 D[i][j] = D[j][i]。

你需要將 n 個物品恰好分成 k 組，每組至少有一個物品。分組後，同一組內的物品之間的距離會被視為無限大，而不同組之間的距離保持不變。

請找出一種分組方式，使所有不同組物品之間的距離中的最小值最大，並輸出這個最大可能的最小距離。

## 輸入格式

第一行輸入兩個整數 `n`、`k`，分別代表物品數量與要分成的組數。

接下來 `n` 行，每行包含 `n` 個整數，表示距離矩陣 `D`。

`D[i][j]` 表示物品 `i` 與物品 `j` 之間的距離。

## 輸出格式

輸出一個整數，表示將 `n` 個物品分成 `k` 組後，不同組之間距離的最小值所能達到的最大值。

## 資料範圍

* `1 <= k <= n`
* `1 <= n <= ?`
* `D[i][i] = 0`
* `D[i][j] = D[j][i]`
* `D[i][j]` 為非負整數。


# 分組遊戲

## 題目想法

一開始我看到這一道題目的時候，我知道它應該要使用二分搜尋，但是一直想不到要如何去做二分搜尋。

後來去查了資料才發現，原來這一題還可以轉換成連通塊問題，而轉換過來之後，這一題就變得非常簡單。

我最後想到可以直接對題目所要求的最小值所能達到的最大值進行二分搜尋，二分搜尋的參數就是假設的最大最小值。

## 解題過程

在二分搜尋的過程中，我會先假設一個最小距離 ove，接著檢查這個 ove 是否可以成立。

檢查的時候，我把兩個物品之間距離小於 ove 的情況視為它們是連通的。

我會先隨便找一個還沒有被走過的點，然後利用 DFS 找到所有和它連通的點。找到一個完整的連通塊之後，再繼續尋找還沒有被走過的點，重複這個過程，最後就可以得到總共有多少個連通塊。

如果連通塊的數量比 k 小，就代表這個 ove 不合格，因為有些連通塊不能再拆開，所以沒有辦法分成 k 組。

如果連通塊的數量比 k 多，則沒有問題，因為不同的連通塊之間可以合併，所以最後仍然可以合併成剛好 k 組。

因此，我只需要利用二分搜尋找出最大的可行 ove，最後輸出二分搜尋得到的結果即可。

## 解題方法思考

一開始我雖然知道這題應該要使用二分搜尋，但是一直找不到要怎麼判斷一個答案是否可行。

後來發現可以把問題轉換成連通塊之後，判斷方式就變得很直觀。

如果兩個物品之間的距離小於目前假設的最小距離，那麼它們就不能被分到不同組，所以必須放在同一個連通塊中。

這樣只要算出連通塊的數量，就可以知道目前假設的答案是否可行。

我覺得這一題比較重要的地方不是 DFS 本身，而是如何把原本的分組問題轉換成連通塊問題。轉換完成之後，剩下的二分搜尋和 DFS 就比較容易處理了。

## 複雜度分析

時間複雜度：

O(n² log 10^8)

每次檢查一個二分搜尋的答案時，需要利用 DFS 檢查每個物品與其他物品之間的關係，因此一次檢查需要 O(n²) 的時間，而二分搜尋需要 O(log 10^8) 次。

空間複雜度：

O(n²)

主要是用來儲存距離矩陣 grid，另外還需要 visited 和 DFS 使用的 stack。

## 學習心得

這一題讓我比較深刻地感受到，看到二分搜尋題目時，真正困難的地方通常不是二分搜尋本身，而是要找到一個方法去判斷目前假設的答案是否可行。

一開始我知道這題可以二分搜尋，卻一直想不到 check 要怎麼寫，所以一直卡住。

後來查了資料之後，我才發現原來可以把這題轉換成連通塊問題。轉換之後，原本看起來很複雜的分組問題，就變成只要找出有多少個連通塊。

這也讓我學到，遇到不容易直接處理的問題時，可以試著把問題轉換成自己比較熟悉的圖論問題。只要找到正確的轉換方式，原本很困難的問題可能就會變得非常簡單。
