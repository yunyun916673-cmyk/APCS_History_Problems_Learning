# Tour

## 題目敘述

有 (N) 個城市與 (M) 條單向道路。每條道路只能按照指定方向通行。

Puma 可以從任意城市出發，經過零條以上的道路後抵達另一個城市。請計算所有可能作為起點與終點的有序城市對數量；起點與終點相同也算一種情況。

## 輸入格式

第一行輸入兩個整數 (N,M)。

接下來 (M) 行，每行輸入兩個整數 (A_i,B_i)，表示有一條從城市 (A_i) 通往城市 (B_i) 的單向道路。

## 輸出格式

輸出可以作為旅程起點與終點的有序城市對數量。

## 資料範圍

* (2<=N<=2000)
* (0<=M<=\min(2000,N(N-1)))
* (1<=A_i,B_i<=N)
* (A_i\ne B_i)
* 所有 ((A_i,B_i)) 皆不重複
* 所有輸入值皆為整數

範例輸入 #1


3 3
1 2
2 3
3 2

範例輸出 #1

7

範例輸入 #2

3 0

範例輸出 #2

3

範例輸入 #3

4 4
1 2
2 3
3 4
4 1

範例輸出 #3

16

# Tour

## 題目想法

一開始看到這題的時候，我注意到不一定某一個城市會和所有城市連通，所以不能只從某一個城市出發就把所有情況算完。因此我想到可以從每一個城市出發，各自走一次，把所有可能的起點和終點配對都算出來。

因為題目要求的是起點和終點的有序 pair，所以我可以固定一個起點，然後從這個起點開始搜尋。每走到一個新的城市，就代表找到一個新的終點，這時候就讓 TOTAL 加上 1。等這個起點能到達的城市都找完之後，再換下一個城市當起點，以此類推。

這樣做的好處是邏輯比較直接，就是把每一個城市都當成起點，然後找出它可以到達的所有終點。

## 解題過程

在 SKDFS 裡面，我先做一個 0 到 N 的迴圈，讓每一個城市都當一次起點。

因為每一次算的是不同的起點和終點 pair，所以每換一個起點，就需要重新建立一個 visited，避免受到前一次搜尋結果的影響。

接著我使用 stack 實作 DFS。先把目前的起點放進 stack，之後不斷取出城市。如果這個城市還沒有被拜訪過，就把它標記成已拜訪，並讓 TOTAL 加上 1，接著把這個城市可以直接到達的其他城市放進 stack。

這樣就可以找到目前這個起點所有可以到達的城市。

當目前的起點搜尋完成後，就換下一個城市重新做一次同樣的操作。最後 N 個城市都當過起點之後，TOTAL 就是所有可以成立的起點和終點有序 pair 數量。

在 main 裡面，完成輸入和鄰接串列的初始化之後，直接輸出 SKDFS 的結果即可。

另外，因為這題的 N 比較大，我一開始有考慮 DFS 深度可能造成遞迴問題，所以沒有使用遞迴 DFS，而是使用 stack 來實作 DFS。

## 解題方法思考

這題我一開始想到這個方法的時候，其實還有些懷疑，因為我擔心如果每一個城市都重新做一次 DFS，會不會造成 TLE。

不過後來看了一下題目的範圍，發現 N 和 M 並沒有大到像 10^5 甚至更大的程度，所以即使每一個城市都做一次 DFS，仍然是可以接受的。

這題的做法就是固定起點，然後找出所有可以到達的終點。因為每一個城市都必須當一次起點，所以總共會做 N 次搜尋。

## 複雜度分析

### 時間複雜度：

O(N(N+M))

因為總共有 N 個城市，每個城市都會做一次 DFS，而一次 DFS 最多會走過 N 個城市以及 M 條道路。

### 空間複雜度：

O(N+M)

鄰接串列需要 O(N+M) 的空間，另外 DFS 使用的 stack 和 visited 也需要 O(N) 到 O(M) 的空間。

## 學習心得

這題讓我比較明確地理解到，有些圖的題目不一定要想辦法從一個地方把所有答案一次算完。如果題目本身是在問很多個起點分別可以到達哪些終點，那麼直接固定起點，一個一個做搜尋，反而會讓整個邏輯變得很清楚。

一開始我也會擔心同一個 DFS 做很多次會不會太慢，但這次讓我發現不能只看到多次 DFS 就直接認為一定會 TLE，還是要先看題目的 N 和 M 範圍，再實際分析時間複雜度。

另外，這題也讓我注意到，如果擔心遞迴 DFS 的深度問題，可以直接使用 stack 寫成非遞迴版本。
