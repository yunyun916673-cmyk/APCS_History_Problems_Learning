# 社團

## 題目敘述

小明需要安排高中社團申請流程的順序。共有 N 個處室，部分處室之間存在先後限制，表示必須先完成某個處室的流程後，才能前往另一個處室。

請判斷是否存在一個符合所有限制的處室訪問順序。若可以完成安排，輸出一個從 1 到 N 的排列，代表小明依序前往各處室的順序；若因為限制互相矛盾，導致無法安排，則輸出 NO。

## 輸入格式

第一行輸入兩個整數 N 與 M，分別代表處室數量以及先後限制的數量。

接下來 M 行，每行輸入兩個整數 a、b，表示必須先經過處室 a，才能經過處室 b。

## 輸出格式

若存在符合所有限制的順序，第一行輸出 YES，接著輸出 N 行，每行一個整數，表示小明依序前往的處室編號。

若不存在可行的順序，則輸出 NO。

# 社團

## 題目想法

一開始看到這一道題目的時候，我很快就想到可以把它轉換成有向圖問題。

因為題目中的限制是「必須先完成某個處室，才能前往另一個處室」，這其實就代表兩個處室之間存在一條有方向的邊。

一開始我思考應該使用 BFS 還是 DFS 來處理這個問題。雖然這是一個圖形搜尋問題，但是這題的重點並不是尋找一條路徑，也不是一直沿著某個方向走到底，而是要找出目前有哪些處室已經符合條件，可以直接前往。

因此我想到使用類似 BFS 的方式，每次先處理目前所有可以前往的處室，完成後再檢查有哪些新的處室因為前置限制解除，也可以加入下一輪。

後來我發現，這其實就是拓樸排序的概念。只要維護每個處室還有多少個前置處室沒有完成，就能判斷目前哪些處室可以開始。

## 解題過程

我先建立 N、M，並使用 SHIP 儲存每個處室之間的關係。

SHIP[i] 中儲存的編號，代表如果要前往那些處室，必須先完成第 i 個處室。

接著建立陣列 CNT，用來記錄每個處室目前還有多少個上級處室沒有完成。

初始化完成後，我先找出所有 CNT 為 0 的處室。

因為 CNT 為 0 代表這個處室沒有任何前置限制，可以直接前往，所以先將它們放入 queue 中。

接著開始進行 BFS。

每次從 queue 取出一個處室：

1. 將它加入 PATH，代表目前已經完成這個處室。
2. 查看這個處室所有可以前往的下一個處室。
3. 將這些處室的 CNT 減少 1，代表其中一個前置條件已經完成。
4. 如果某個處室的 CNT 變成 0，代表所有前置條件都完成，可以加入 queue。

一直重複這個流程，直到 queue 為空。

最後檢查 PATH 是否包含全部 N 個處室。

如果數量不足，代表存在互相矛盾的限制，也就是圖中存在環，因此無法安排順序。

## 解題方法思考

這一題本身其實不算困難，主要的關鍵是要想到如何表示「還有多少前置條件沒有完成」。

如果沒有維護 CNT，可能會不知道一個處室目前是否真的可以前往，也很難判斷限制是否互相矛盾。

一開始雖然想到使用 BFS，但是一般 BFS 只是在圖上搜尋，並不能直接解決這種有先後順序限制的問題。

後來透過維護每個節點的入度，讓每次加入 queue 的處室都代表目前已經符合所有條件，這樣就能完成拓樸排序。

這也讓我了解到，有些圖論問題雖然看起來像 BFS 或 DFS，但真正需要的是根據問題特性維護額外資訊。

## 複雜度分析

時間複雜度：

O(N+M)

每個處室最多會加入 queue 一次，而每條限制邊也只會被檢查一次。

空間複雜度：

O(N+M)

需要使用 SHIP 儲存 M 條邊，以及使用 CNT、queue 和 PATH 儲存 N 個處室相關資訊。

## 學習心得

這一題讓我更加理解拓樸排序的概念。

以前遇到圖形問題時，常常會先想到 BFS 或 DFS，但這題讓我發現，單純的搜尋方式不一定能解決問題，還需要根據題目的限制設計額外的紀錄方式。

透過 CNT 記錄每個處室還需要多少前置條件，我可以更清楚地判斷目前哪些狀態是可以進行的。

雖然這題的演算法本身不算複雜，但它訓練了我將實際問題轉換成圖模型的能力，也讓我對拓樸排序有更深的理解。
