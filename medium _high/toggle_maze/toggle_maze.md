# 開關迷宮

## 題目敘述

有一個具有 **H** 列、**W** 欄的網格。令 **(i, j)** 表示從上往下第 **i** 列、從左往右第 **j** 欄的格子。每個格子的狀態以字元 **Aᵢ,ⱼ** 表示，其意義如下：

- `.`：空格。
- `#`：障礙物格。
- `S`：起點格。
- `G`：終點格。
- `o`：開啟的門。
- `x`：關閉的門。
- `?`：開關格。

高橋可以在一次操作中，從目前所在的格子移動到相鄰的格子（上、下、左、右），前提是該格子既不是障礙物格，也不是關閉的門。

此外，每當他移動到一個開關格時，所有開啟的門都會變成關閉的門，而所有關閉的門都會變成開啟的門。

請判斷他是否能從一開始位於起點格的狀態移動到終點格；如果可以，請找出所需的最少操作次數。

## 限制

- 1 ≤ **H, W** ≤ 500
- **H** 和 **W** 為整數。
- 每個 **Aᵢ,ⱼ** 都是 `.`, `#`, `S`, `G`, `o`, `x`, `?` 中的一個。
- `S` 和 `G` 在 **Aᵢ,ⱼ** 中各恰好出現一次。

輸出

範例輸入 2

# 開關迷宮

## 題目想法

一開始我看到這一道題目的時候，就覺得它很像我小時候玩的密室逃脫。

在這一題裡面，`o` 和 `x` 就代表有些地方原本可能是開的，但是一旦踩到 `?` 格子，那麼原本開的門就會變成關的，而原本關的門就會變開的。

這跟我小時候玩的一個密室逃脫很像，原本一切都正常的，結果走進另外一個房間之後，一切都倒過來了，例如可能椅子被黏在天花板上之類的。

所以我就想說，既然它這邊會出現不同的地圖，那麼我就額外再多開一個維度來對它進行處理。

因此我的 `visited` 就用了三個維度，前兩個維度記錄目前所在的列和欄，第三個維度則記錄目前是在 0 地圖還是 1 地圖。

## 解題過程

我在初始化完成之後，為了待會方便，所以我就用 `get_typ` 來翻譯題目給的 `char`。

這樣在 BFS 裡面進行判斷的時候，就可以直接透過數字來判斷目前走到的是什麼格子。

在 BFS 裡面，我的 queue 給它三個參數：

row 座標
col 座標
目前處在 0 還是 1 的地圖

因為題目要求的是最短路徑，所以我這裡的 BFS 有使用 level 來分層。

在每一次移動時，我會先判斷下一個格子能不能走。如果是障礙物，或是在目前地圖狀態下關閉的門，就不能走。

如果我走到了問號的格子，那麼我只要把目前的地圖狀態反轉：

0 地圖 → 1 地圖
1 地圖 → 0 地圖

然後再把新的狀態放進 queue 裡面繼續進行 BFS。

這樣我就不需要真的去修改整張地圖，只需要記錄現在是哪一種地圖即可。

另外，因為同一個位置在不同地圖下可能會有不同的結果，所以 visited 不能只記錄 row 和 col，而是要把地圖狀態也記錄進去。

也就是：

visited[row][col][map]

如果我走到了終點，那麼就代表找到了起點到終點的最短路徑。

因為 BFS 是一層一層搜尋，所以第一次走到終點時，一定就是最短路徑。

這時候目前的 level 是移動到終點前的距離，所以只要輸出 level + 1 就可以了。

而在 main 裡面，也只需要在初始化完成之後輸出 bfs() 的回傳值就行了。

## 解題方法思考

我覺得這一題比較重要的地方，是發現地圖的狀態本身也需要被加入 BFS 的狀態。

如果只記錄目前的位置，那麼同一個位置可能會因為之前有沒有踩過問號，而有完全不同的情況。

例如同樣走到 (r,c)：

(r,c,0)
(r,c,1)

這兩個狀態雖然位置相同，但是門的狀態不同，所以後面可以走的路也可能不同。

因此我最後就把地圖狀態一起放進 BFS，讓一個完整的狀態變成：

(row, col, map)

另外，我原本也可以直接在踩到 ? 的時候，把所有的 o 和 x 互換。

但是這樣每次切換都要處理整張地圖，沒有必要。

因為所有門的狀態其實只需要知道目前被切換了幾次，而真正有影響的只有奇數次還是偶數次。

所以我只需要使用 0 和 1 來表示目前的地圖狀態，就可以完成整個切換的效果。

最後再使用 BFS，就可以找到從起點到終點的最短路徑。

## 複雜度分析

### 時間複雜度：

O(HW)

因為每一個格子最多會在 0 地圖和 1 地圖這兩種狀態下各被拜訪一次，所以總狀態數最多是 2HW。

每個狀態最多檢查四個方向，因此整體時間複雜度為 O(HW)。

### 空間複雜度：

O(HW)

主要需要儲存 grid、三維的 visited，以及 BFS 使用的 queue。

雖然多了一個地圖狀態的維度，但只有 0 和 1 兩種狀態，因此仍然是 O(HW)。

## 學習心得

這一題讓我發現，BFS 不一定只能把目前的位置當成狀態。

以前想到 BFS 的時候，我比較容易直接想到目前在哪一個座標，但是這一題讓我發現，如果同一個位置在不同情況下會有不同的後續結果，那麼就需要把這個額外的資訊也加入 BFS 的狀態。

這次我就是把地圖分成 0 和 1 兩種狀態，再把它加入 visited 和 queue 裡面。

而且我覺得這題也讓我學到，不一定真的要去修改整張地圖。

原本看到踩到 ? 之後所有的 o 和 x 都會交換，我可能會想到直接把地圖修改掉，但後來發現其實只要知道目前是第幾種地圖就可以判斷門能不能走。

這樣可以讓程式簡單很多，也不用一直修改整張地圖。

我覺得這也是我這題比較重要的一個收穫：當題目中的狀態會改變時，不一定要真的去修改所有資料，有時候只要把造成變化的資訊額外記錄下來，就可以用狀態來表示整個情況。
