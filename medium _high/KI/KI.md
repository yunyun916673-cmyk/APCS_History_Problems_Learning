# Ki

## 題目敘述

給定一棵有根樹，共有 **N** 個頂點，編號為 1 到 **N**。根節點為頂點 1，第 *i* 條邊（1≤*i*≤*N*−1）連接頂點 *aᵢ* 和 *bᵢ*。

每個頂點上都有一個計數器。初始時，所有頂點上的計數器值皆為 0。

現在將進行以下 **Q** 次操作：

- 第 *j* 次操作（1≤*j*≤*Q*）：將以頂點 *pⱼ* 為根的子樹中，每一個頂點的計數器增加 *xⱼ*。

請求出所有操作完成後，每個頂點上的計數器值。

## 限制

- 2≤*N*≤2×10⁵ 
- 1≤*Q*≤2×10⁵ 
- 1≤*aᵢ*<*bᵢ*≤*N* 
- 1≤*pⱼ*≤*N* 
- 1≤*xⱼ*≤10⁴ 
- 給定的圖是一棵樹。 
- 輸入中的所有數值皆為整數。 

## 輸入

輸入格式如下：

N Q

a₁ b₁

:

aₙ₋₁ bₙ₋₁

p₁ x₁

:

pQ xQ

## 輸出

依序輸出頂點 1、2、…、N 上的計數器值，數值之間以空格分隔。

# Ki

## 題目想法

一開始看到這一道題目，當我看到 N 的範圍的時候，我就知道這一題是要預先處理的。

如果要預先處理的話，那麼按照題目的要求，一個一個的去記錄說，哪些節點的計數器的值要加上 x，這樣絕對會 TLE。

所以我就想了，要不直接先算出每一個節點它包括自己的以下的所有節點，總共需要加多少個。然後對於每一個節點都這樣求它的值，然後最後我只需要進行一次 DFS 就好了。

然後因為我怕說深度爆炸，所以我這裡用 STACK 代替遞迴 DFS。

## 解題過程

我先用 TEMP 記錄每一個節點本身總共需要增加多少。

讀取每一個操作的時候，我就直接把 X 加到對應節點的 TEMP 裡面：

temp[p]+=x;

這樣就不用每一次操作都真的去遍歷整個子樹，而是先把所有操作累積起來。

接下來我進行一次 SKDFS，從根節點 1 開始往下走。

在 SKDFS 裡面，我的 SCK 裡面存的參數有三個，一個是目前在哪個節點，一個是它的上一級節點是誰，以及這一個節點往下所需要增加的值。

之所以要用它的上一級節點，是因為從題目的輸入當中，我沒有辦法去判斷說誰是它的上級節點，因為輸入的邊是用無向圖的方式給出的，所以需要 PNT 來記錄目前節點的父節點。

在 SKDFS 裡面，我每到一個節點，就把它所帶來的 VAL 加到這個節點最後的答案 ANSWER：

answer[pwd]+=val;

然後繼續往下走。

如果目前要走到 CHD，就把目前累積的 VAL 加上 CHD 自己的 TEMP：

sck.push({chd,pwd,temp[chd]+val});

這樣原本祖先節點需要增加的值，就可以一路往下傳到它的所有子孫，而每一個節點自己需要增加的值也會在往下傳遞的過程中加入。

最後在 MAIN 裡面完成初始化之後，進行一次 SKDFS，然後把 ANSWER 的內容依序輸出就行了。

## 解題方法思考

一開始我想到這一題的 N 範圍很大，所以如果每一次操作都直接去找 P 所代表的子樹，然後把裡面的每一個節點都加上 X，最壞的情況下會需要處理非常多次的節點，時間複雜度會太高。

所以我把原本每一次都要處理整個子樹的操作，改成先把每個節點自己需要增加的值記錄起來。

之後只需要從根節點開始做一次 DFS，把目前累積的值往子樹傳下去，就可以得到每個節點最後的答案。

因為題目給的是無向圖，所以在 DFS 的時候需要額外記錄上一個節點 PNT，避免走回上一個節點。

另外，我原本如果直接使用遞迴 DFS，因為 N 最大可以到 2×10⁵，所以如果樹的深度非常深，可能會有遞迴深度過大的問題。因此最後選擇使用 STACK 來實作 DFS，讓這個部分更加穩定。

## 複雜度分析

### 時間複雜度：

O(N + Q)

讀取 Q 次操作需要 O(Q)，最後的 DFS 會走過所有 N 個節點與 N−1 條邊，因此需要 O(N)，總共就是 O(N + Q)。

### 空間複雜度：

O(N)

需要使用鄰接串列保存整棵樹，以及 TEMP、ANSWER 和 STACK 等資料結構，因此空間複雜度為 O(N)。

## 學習心得

在做完這一題的時候，我發現原來我最近一直做這些需要預先處理的題目，已經有一定的成果了。

因為我看到這一道題目，看到 N 的範圍之後，一下子就想到它究竟要怎麼去做預先處理，而不是先嘗試直接按照題目的操作一個一個模擬。

這也讓我發現，我現在看到題目的時候，開始會先注意資料範圍，再去思考目前的做法會不會 TLE，而不是直接開始寫程式。

這一題也讓我更加熟悉了如何在樹上利用 DFS 傳遞累積的資訊，以及在可能有深度爆炸的情況下，用 STACK 取代遞迴 DFS。
