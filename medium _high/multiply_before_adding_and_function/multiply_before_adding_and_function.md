# 先加後乘與函數

## 題目意思

給定一個運算式，內容包含數字、`+`、`*` 以及函數 `f()`。需要依照題目規定的「先加後乘」規則計算整個運算式。

函數 `f(x1, x2, ..., xn)` 的結果為所有參數中的最大值減去最小值。函數可以巢狀出現。

## 輸入格式

輸入一行運算式。

## 輸出格式

輸出運算式依照規定計算後的結果。

## 範圍限制

- 運算式只包含題目規定的合法字元與語法。
- 運算式長度不超過 500。
- `f()` 的參數數量不固定。
- `f()` 可以巢狀使用。
- 除了函數 `f()` 之外，不會有其他括號。

## 範例輸入 1

```
2+3*1+2+1
```

## 範例輸出 1

```
20
```

## 範例輸入 2

```
12+f(13,2+f(8,1+2*3),1+1*f(20,4)*f(2))*2
```

## 範例輸出 2

```
50
```

## 範例輸入 3

```
f(0)
```

## 範例輸出 3

```
0
```


# 先加後乘與函數

## 題目想法

這一題其實我很早就開始接觸了，結果後來用分詞的 SPLIT，成功寫出來過一次，但整體邏輯變得非常複雜。直到現在，我嘗試了好多次之後，才終於想出這一題到底要怎麼做。

因為我其實很早就發現，可以用乘法符號和加法符號進行字串切割，或是直接由左到右，用一個指標直接掃過去，這兩種方法我也都各個嘗試過很多遍。但最後還是因為要維護的規則太多而卡住了。

於是這時候我就想說，既然要維護的規則那麼多，我能不能直接把它用一個個函式進行處理？因為這題本身就是一個函式嘛。

所以我在程式裡面就用了 T、G、F 三個函式，並且讓函式互相嵌套，形成一個三角的循環關係。這是我第一次想到並且實作這一種函式的應用方式。

以前這一種方式只出現在方向為單向、一直往下深入的 DFS 遞迴當中，而如今這一種三角的循環結構，是我之前從來沒有使用過的。

## 解題過程

我先從 T 開始處理。

T 裡面，我把一個 string 用乘法符號進行分隔，然後把分隔出來的內容丟給 G 做處理，再把 G 回傳的結果互相乘起來。

這樣處理沒有問題，因為題目的規則本來就是先加後乘，所以我可以先把每一段加法處理完，再把每一段的結果乘起來。

接下來是 G。

G 和 T 很像，只不過 G 是用加法符號進行分割，然後把每一段丟給 F 進行處理，再把結果全部加起來。

最後是 F。

在 F 裡面，如果整串都是數字的話，那就直接回傳這個數字就行了。

但如果不是整串數字，就要再判斷這一段是不是 f 函式。

如果是 f 函式的話，就先把最前面的 f( 和最後面的 ) 去掉，接下來的處理方式就又和 G、T 很像，只不過這次是使用逗號進行分隔。

每一個參數都會被丟給 T 做處理，最後再把所有參數的最大值和最小值找出來，回傳最大值減最小值的結果。

如果這一段不是 f 函式，而是一個一般的運算式，那麼就直接把它丟給 T 處理。因為如果只有一個項目，那麼最後最大值和最小值本來就會相同，所以結果自然就是 0。

就這樣讓同一段字串在 T、G、F 三個函式之間不斷循環，逐層篩選，最後留下最乾淨的結果，再一層一層把結果回傳上來。

在這三個函式當中，我都有使用一個 target。

這是為了跳過函式套函式，以及函式裡面的加法符號和乘法符號。我真正要分割的只有最上面那一層結果，至於裡面的其他函式、加法和乘法，通通丟給下一層進行遞迴處理。

例如在處理 f 函式的時候，如果裡面又有另一個 f 函式，那麼內層的逗號就不能被當成外層的分隔符號。

同樣地，如果現在正在處理一個 f 函式，裡面出現加法或乘法，也不能直接被外層的 G 或 T 切開。

所以我會用 target 記錄目前進入了幾層函式，只有當 target 回到 0 的時候，才代表目前遇到的符號真的屬於最外層，可以進行分割。

## 解題方法思考

這一題我一開始其實一直想用字串切割的方式處理。

我曾經使用過 SPLIT 的方式成功寫出來一次，但是那時候整體邏輯非常複雜。後來我也嘗試過直接從左到右用一個指標掃過去，但因為同時要處理加法、乘法、函式、巢狀函式以及逗號，每一種規則都要自己維護，所以最後還是很容易卡住。

後來我才想到，與其把所有規則全部塞在同一個函式裡面，不如把不同層級的規則分開。

因此我把它拆成 T、G、F 三個函式。

T 專門處理乘法，G 專門處理加法，F 則負責處理最底層的數字或函式。這樣每個函式只需要處理自己負責的規則，再把其他問題交給下一層。

這也是我第一次真正使用這種函式互相呼叫的方式。

以前我比較常接觸的遞迴，像 DFS，通常都是從一個點一直往下一層深入。但這一次的 T、G、F 卻形成了一個循環：

T → G → F → T

我第一次發現，函式並不一定只能單方向一直往下遞迴，也可以透過不同函式之間的互相呼叫，讓問題在不同層級之間不斷跳躍，直到符合某一個條件後停止，再把結果逐層回傳。

我覺得這是這一題對我來說最有價值的地方。

## 複雜度分析

時間複雜度：

O(n²)

因為在 T、G、F 三個函式之間會不斷切割與建立新的 string，而且 substr 也需要複製字串，所以最壞情況下可能需要重複掃描字串。

空間複雜度：

O(n)

主要來自函式之間的遞迴呼叫，以及每一層暫存的 string。

不過因為題目的運算式長度最多只有 500，所以這樣的複雜度可以接受。

## 學習心得

寫完這一題之後，雖然我花了很久的時間去嘗試各種方式，但是我真的完成的那一刻，我覺得是很充實的。

因為我不僅把一個曾經熟悉的演算法重新拿回來，去做了一個新的應用處理，也第一次使用了這種多個函式互相嵌套、循環呼叫的方式。

以前我對遞迴的印象比較偏向 DFS 那種一直往下深入，但這一題讓我發現，遞迴其實不一定只能是單方向的。只要每個函式都有明確的責任，並且能夠把問題交給適合的下一個函式處理，就可以形成不同層級之間的循環。

除此之外，這一題也讓我對字串處理以及手動維護規則有了更深刻的認知。

以前遇到這種題目，我比較容易想著怎麼把整個字串直接切開，但當規則越來越多、又有函式巢狀的時候，單純切割就會變得非常複雜。

這次我則是反過來，把不同規則拆成不同函式，再利用 target 去判斷目前是不是在更深層的函式裡面。這讓我第一次感受到，把複雜問題拆成不同層級處理，真的可以讓原本很混亂的字串問題變得清楚很多。
