# 機器人的路徑

## 題目意思

有一張 n×m 的地圖，每個格子都有一個不同的非負整數。

機器人會從數值最小的格子開始移動，每次選擇上下左右四個相鄰格子中，數值最小且尚未走過的位置前進。

當目前位置周圍沒有符合條件的格子可以移動時，機器人停止。

請計算機器人走過的所有格子數值總和。

## 輸入格式

第一行輸入兩個整數 n, m，代表地圖的大小。

接下來輸入 n 行，每行包含 m 個整數，表示地圖中每個格子的數值。

## 輸出格式

輸出一個整數，表示機器人移動路徑上所有經過格子的數值總和。

# 機器人的路徑

## 題目想法

一開始看到這個題目的時候，我就認定它是一道模擬題，因為題目描述的是機器人會按照固定規則一直移動下去，所以我只需要模擬它每一步的移動即可。

不過我後來注意到，這題的移動方式和一般搜尋問題不太一樣。它不是從一個位置向外擴散尋找所有可能路徑，而是一個角色按照規則一直往前走，因此不需要像 BFS 一樣維護大量狀態。

所以我選擇使用 DFS 來處理這題，讓函式負責模擬機器人目前所在的位置，然後不斷找到下一個要走的位置並繼續執行。

思考過程中，我覺得這題最核心的地方不是 DFS 本身，而是每一步如何找到上下左右四個方向中數值最小且沒有走過的座標。


## 解題過程

首先我先初始化上下左右移動需要使用的方向陣列 DR 和 DC，方便之後檢查四個方向。

接著建立需要使用的變數：

- n、m 紀錄地圖大小
- SR、SC 紀錄機器人的起點
- GRID 儲存整張地圖
- Visited 紀錄哪些位置已經走過
- Total 紀錄最後路徑上的數字總和

在 WALK 函式中，我會先將目前所在格子的數值加入 Total，並將這個位置標記成已經走過。

接著使用四次迴圈檢查上下左右四個方向。

我會另外維護兩組座標：

- TR、TC 代表目前檢查到的鄰近位置
- NR、NC 代表目前找到的最小值位置

每次找到一個沒有走過且數值更小的位置，就更新 NR、NC。

等四個方向都檢查完成後：

- 如果沒有找到新的位置，代表機器人已經沒有路可以走，直接結束。
- 如果有找到，就繼續呼叫 WALK，移動到新的位置。

最後在 MAIN 函式中：

先輸入 n、m，重新設定 GRID 和 Visited 的大小。

接著輸入地圖資料，並且在輸入的同時找出最小值的位置，作為機器人的起點 SR、SC。

完成後執行 WALK 函式，最後輸出 Total。


## 解題方法思考

一開始我想到的是直接模擬機器人的移動，因為題目的規則非常明確，每一步只需要決定下一個位置。

如果使用其他搜尋方式，例如 BFS，需要維護很多可能狀態，但這題其實不存在分支選擇，因為機器人每一步只有一個符合條件的方向。

因此使用 DFS 反而更加符合題目的特性。

這題實作時比較需要注意的是如何找出四個方向中的最小值。我選擇使用額外維護一個座標 NR、NC 的方式。

藉由保存目前找到的最佳位置，再和下一個方向比較，就可以簡單地得到四個方向中的最小值，也讓程式比較容易閱讀。


## 複雜度分析

時間複雜度：

O(n*m)

原因：

每個格子最多只會被機器人走一次，而每次走到一個格子時，只需要檢查固定的四個方向，因此總時間和地圖大小成正比。


空間複雜度：

O(n*m)

原因：

需要使用 GRID 儲存地圖，以及使用 Visited 記錄已經走過的位置。

另外 DFS 遞迴最深可能走過所有格子，因此遞迴空間也是 O(n*m)。


## 學習心得

這題讓我練習如何把題目的規則直接轉換成程式流程。

以前遇到搜尋題時，我比較容易想到 BFS 或 DFS，但這題讓我更清楚了解，不是所有走路問題都需要搜尋所有可能狀態。

如果題目中的角色移動方式是固定規則，只需要一直根據條件選擇下一步，那其實可以直接模擬。

另外這題也讓我練習如何處理局部選擇問題。找到四個方向中的最小值看似簡單，但如果沒有整理好目前最佳位置，很容易寫出很多重複判斷。

透過維護 NR、NC，我學會了利用額外資訊簡化程式邏輯，也讓之後遇到類似需要比較多個選項的問題時，可以想到使用相同的方法。
