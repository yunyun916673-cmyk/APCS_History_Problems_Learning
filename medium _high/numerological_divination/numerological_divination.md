# 數位占卜

# 題目敘述

有 `m` 支籤，每支籤都是由英文小寫字母組成的字串。

任取兩支不同的籤 `S`、`T`，將它們依序連接成 `S + T`。如果連接後的字串可以被分成長度相同、內容完全相同的左右兩半，則這一對籤稱為符合條件的 pair。

題目保證若 `S + T` 符合條件，交換順序形成 `T + S` 也會符合，因此相同的兩支籤只計算一次。

請計算所有籤中共有多少組 pair 符合條件。

## 輸入格式

第一行輸入一個正整數 `m`。

接下來有 `m` 行，每行輸入一個由英文小寫字母組成的字串。

## 輸出格式

輸出一個整數，代表符合條件的 pair 數量。

## 範圍限制

- `1 <= m <= 50000`
- 每個字串的長度最多為 `100`
- 所有字串皆不相同。

# 數位占卜

## 題目想法

一開始看到這一道題目的時候，我也是卡住了一陣子，但後來去問了問題之後才發現，原來這一題可以用非常簡潔的方法處理掉。

因為每一個字串的長度非常小，所以可以直接對同一個 string 做拆解的動作。

假設有兩個字串 PIEP 和 IE，它們可以組成 PIEPIE。

如果我設 A 等於 PIE，那麼 PIEP 可以看成 A 加上 X，而 IE 可以看成 Y，並且 X 加上 Y 等於 A，也就是 PIE。

所以我可以反過來對 PIEP 做拆解的動作。

例如把 PIEP 拆成 P、IE、P，我發現左右兩邊的 P 相等，那麼如果後面再多加一個 IE，就會變成：

PIEP + IE = PIEPIE

這時候就會是一個符合條件的 pair。

所以我只要去找有沒有一個字串叫做 IE，如果有的話，就代表找到了一組 pair。

如果字串更長也是一樣的概念。

例如我可以把 ABCCAB 拆成 AB、CC、AB，因為左右兩邊的 AB 相等，所以這時候只要去找有沒有一個叫做 CC 的字串，就能知道有沒有這一個配對。

因此這一題的重點並不是直接去枚舉兩個字串，再把它們接起來判斷，而是反過來固定其中一個字串，看看它能不能拆成 A、B、A 的形式。如果可以，再去確認中間的 B 是否存在。

## 解題過程

我先建立 M，然後用 COLA 去記錄每一個字串，再使用 POPCORN 來幫助我快速查找某個字串是否存在。

在 main 裡面，我先輸入 M，並把 COLA 的大小設為 M，ANS 設為 0，這是待會最後要輸出的配對數量。

接著輸入所有的字串，同時把每一個字串加入 POPCORN，這樣之後就可以快速確認某一個拆出來的字串是否存在。

接下來對於 COLA 裡面的每一個字串，都去做拆解的動作。

我會嘗試不同的拆解位置，將目前的字串拆成：

A + B + A

如果左右兩邊的 A 不相同，就代表這種拆法不可能形成符合條件的 pair，因此直接跳過。

如果左右兩邊相同，就代表只要中間的 B 也是一支籤，就可以形成一組 pair。

因此我再利用 POPCORN 檢查 B 是否存在。

如果存在，就把 ANS 加一。

最後將 ANS 輸出即可。

## 解題方法思考

我覺得這一題真正有趣的地方，是它原本看起來好像需要去枚舉很多不同的字串配對，但找到規律之後，整題就變得非常簡單。

我一開始確實有卡住，但後來發現可以把問題反過來想。

與其直接拿兩個字串去判斷它們接起來是不是左右相同，不如固定其中一個比較長的字串，直接把它拆成 A、B、A，然後只需要確認 B 有沒有出現在所有籤裡面。

因為題目中的字串長度最多只有 100，所以即使要嘗試很多種拆法，總體來說也不會造成太大的效率問題。

另外，我使用 POPCORN，也就是 unordered_set，讓我可以快速確認拆出來的 B 是否存在。

所以這題對我來說，比較重要的不是學到一個很複雜的演算法，而是學到如何從題目的條件中找出規律。

## 複雜度分析

時間複雜度：

O(mK²)

其中 K 是每個字串的最大長度。

因為最多有 m 個字串，每個字串最多嘗試 K 種拆法，而每次拆解字串最多需要 O(K) 的時間。

空間複雜度：

O(mK)

因為需要使用 COLA 和 POPCORN 儲存所有字串。

## 學習心得

我覺得這一題其實是在考驗學生能不能把一個原本看起來很複雜的問題，找出它真正的規律。

一開始看到這一題的時候，我確實覺得要直接去找兩個字串的配對會很麻煩，但後來找到 A、B、A 的規律之後，整題就突然變得非常簡單。

這也讓我發現，有些題目不一定需要使用很複雜的演算法，真正重要的是能不能從題目的條件中找到適合的切入點。

這一題讓我比較深刻地體會到，當一個問題看起來很複雜的時候，可以先不要急著直接實作，而是先試著找出其中的規律。找到規律之後，原本很複雜的問題可能就會變得非常簡單。
