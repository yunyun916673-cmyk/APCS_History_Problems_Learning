# 無人機貨物配送
## 題目意思
在一個 100x100 的正方形網格（左下角座標為 (0,0)，右上角座標為 (99,99)）中，有一台無人機需要從起點將包裹運送到指定的終點。網格中散佈著若干個禁飛區（障礙物）。

無人機的移動方式類似於「象棋中的馬」（即走日字型）。具體來說，無人機每次移動最多有 8 個目標落點，但會受到十字相鄰位置（即所謂的「絆馬腳」位置）是否為障礙物所限制。

以座標變化來看，若無人機目前位置為 (x, y)：

當上方 (x, y+1) 沒有障礙物時，才可選擇移動至 (x-1, y+3) 或 (x+1, y+3)。

當下方 (x, y-1) 沒有障礙物時，才可選擇移動至 (x-1, y-3) 或 (x+1, y-3)。

當左方 (x-1, y) 沒有障礙物時，才可選擇移動至 (x-3, y-1) 或 (x-3, y+1)。

當右方 (x+1, y) 沒有障礙物時，才可選擇移動至 (x+3, y-1) 或 (x+3, y+1)。

所有的移動落點均不得超出網格邊界 (0~99)，且無人機的落點不能是禁飛區（障礙物）。
請求出無人機從起點抵達終點所需的最少移動步數；若無法抵達終點，則視為不可能達成任務。

## 輸入格式
第一行為一個整數 n，代表障礙物的個數。
接下來的 n 行，每行有兩個整數，以一個空白隔開，代表每個障礙物的 x 與 y 座標。
倒數第二行有兩個整數，以一個空白隔開，代表無人機起點的 x 與 y 座標。
最後一行有兩個整數，以一個空白隔開，代表終點的 x 與 y 座標。

注意：輸入的障礙物、起點、終點皆會在不同的位置。

## 輸出格式
若無人機可以依循規則抵達終點，請輸出其所需的最少步數。
若無法到達終點，請輸出單字 impossible。

## 範圍限制
障礙物數量 n 範圍：0 <= n <= 1000

所有橫、縱座標 (x, y) 範圍：0 <= x <= 99 且 0 <= y <= 99

座標皆為整數

# 無人機貨物配送
## 題目想法
一開始看到這個題目，就能立刻辨認出這是一題純粹的最短路徑模擬題。非常直覺地決定使用廣度優先搜尋 (BFS) 來模擬無人機往每個方向的行走狀態，藉此找出最快抵達終點的步數。
## 解題過程
實作 BFS 的擴展時，將無人機的 8 個移動落點依據「絆馬腳」的限制分為 4 組（4 乘以 2 的概念）。在每一次移動前，程式會先去判斷目前所在位置的「方向鄰居」（相鄰格子）是否為障礙物；只有在確認該方向沒有障礙物阻擋後，才會進一步嘗試去走該方向對應的 2 個落點，並將合法的落點加入佇列中。
## 解題方法思考
在處理方向判定時，其實看程式碼就能明顯發現中間有一大段是重複的區塊。我心裡很清楚，更優雅的解法是將座標的位移參數存入陣列中，透過 0 到 3 的迴圈索引直接帶入，這樣就能將 4 段重複的邏輯簡化為 1 段。不過實作當下為求快速（承認有點小偷懶），就直接選擇了「複製貼上」然後手動修改引數的方式來完成。
## 複雜度分析
### 時間複雜度：O(R * C)，
其中 R 和 C 分別為網格的長與寬（100 * 100）。在 BFS 中，最壞情況下網格中的每一個座標最多只會被走訪並推入 Queue 一次，執行效率非常高。
### 空間複雜度：O(R * C)，
記憶體主要消耗在紀錄 100 * 100 二維網格狀態（障礙物與走訪紀錄），以及 BFS 過程中所使用的 Queue，空間消耗都在常數範圍內。
## 學習心得
這次雖然靠著「複製貼上法」順利且快速地把題目給解出來了，但也算是再次驗證了方向陣列（Direction Arrays）在這類網格題型中的重要性。雖然直接複製貼上在當下感覺比較輕鬆省事，但也確實讓程式碼變得冗長。未來如果再碰到類似的題目，會期許自己多跨出那一步，把參數陣列建起來，讓整體程式碼看起來更精簡漂亮！
