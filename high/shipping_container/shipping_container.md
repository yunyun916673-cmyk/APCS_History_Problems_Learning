# 貨櫃
## 題目意思
一座貨運碼頭準備將 n 批貨物裝上同一艘貨櫃船，船上有兩個貨艙，希望能盡量把貨物平均分配到兩個貨艙，使兩個貨艙的總重量差值越小越好。每批貨物都有各自的重量，且單批貨物的重量上限為 k。請找出最佳分配方式，並輸出兩個貨艙各自的總重量。

## 輸入格式
第一行包含兩個正整數 n 與 k，分別代表貨物批數與單批貨物重量的最大值。
接下來有 n 行，每行一個正整數，依序代表第 1 批到第 n 批貨物的重量。

## 輸出格式
輸出一行，包含兩個以空白隔開的整數，分別代表分配後較輕貨艙的總重量與較重貨艙的總重量。

## 範圍限制
1 <= n <= 500

0 <= k <= 100

每批貨物的重量皆為 1 到 k 之間的正整數

所有貨物總重量不超過 50000

# 貨櫃

## 題目意思
給定 n 批貨物各自的重量（單批上限為 k），希望將所有貨物分成兩個貨艙，讓兩個貨艙的總重量差值盡可能小，最後輸出較輕與較重貨艙各自的總重量。

## 解題過程
一開始思考時，容易把問題看成需要同時記錄兩個貨艙各自總重的二維狀態，但後來發現只要算出其中一邊可達到的總和 val，另一邊的總重量就是 total - val，兩者差值為 abs(val - (total - val))。因此可以直接把狀態壓縮成一維布林陣列，並改用 bitset 搭配左移位元運算 dp |= (dp << w) 批次更新所有可能湊出的重量，最後從 total / 2 往下掃描第一個成立的總和即可求得最佳切分，再以 min 和 max 輸出兩邊總重。

## 解題方法思考
這題本質上是子集合和（Subset Sum）與最小差值分割問題。若用傳統二維 DP 記錄兩個貨艙重量會讓狀態空間變得冗餘；改用一維狀態後，只要關注單側可湊出的重量 val，就能直接用 total - val 反推另一側，大幅降低思考與實作複雜度。進一步用 bitset 取代一般陣列做轉移，能把原本逐格轉移的迴圈變成位元平行位移，在 n <= 500、總和不超過 50000 的規模下執行效率非常高。

## 複雜度分析
### 時間複雜度：O(n * W / 64) 
（或以位元運算角度視為 O(n * W) 除以字元寬度），其中 n 為貨物批數，W 為貨物總重量上限（本題約 50000）；每次位移與位元或運算常數極小，可輕鬆在時限內完成。

### 空間複雜度：O(W / 8) 
（使用固定大小的 bitset），僅需儲存可達到的重量狀態位元，記憶體用量遠小於傳統 DP 陣列。

## 學習心得
這題最大的收穫是「降維與對稱性」的觀察：一開始沒立刻想到把二維狀態轉成一維，直接用 total - val 就能帶出另一邊的重量，其實很多雙邊分配或差值最小化題目都能這樣化簡。搭配 bitset 做狀態轉移，也讓我在面對總和上限明確的子集合和問題時，多了一個既簡潔又快速的實作工具。
