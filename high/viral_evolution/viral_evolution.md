# 病毒演化
## 題目想法
一開始看到這個題目的時候，其實我不太知道要如何處理。因為題目給的是一整段長度為 m 的 RNA 字串，我當時沒有想到可以把整個字串拆成一個一個字元，
分別處理每一個位置的變化。因此，我一直找不到具體的操作方式，不知道要如何處理未知的 @，以及如何計算整棵病毒演化樹的最小變異距離。
後來參考了這題的解法，我才恍然大悟：原來每一個 RNA 位置其實可以獨立處理！也就是說，可以把一個長度為 m 的 RNA 序列，拆解成 m 個不同的小問題，
每一次 DFS 只需要考慮其中一個位置的 A、U、C、G 變化即可。
## 解題過程
在確立了「每個位置獨立處理」的核心思維後，程式碼經歷了三次迭代：

### 初步實作（空間壓縮版）：
先根據理解的解法，實作出對每個位置獨立進行 DFS 的版本，每次 DFS 動態更新 DP 狀態。

### 重新推導（三維 DP 版）：
過了一個多禮拜後，為了測試自己是否真的吸收，我不看原本的程式碼，自己重新推導狀態與轉移式，寫出了 dp[病毒編號][RNA位置][字元種類] 的三維 DP。雖然空間較大，但這是我真正靠自己推導出的邏輯。

### 最終優化（拓撲排序 Bottom-up 版）：
今天的最新版本中，我將原本的遞迴 DFS 改成了利用 Queue 進行拓撲排序的迭代寫法。

先建立各節點的父子關係，並記錄每個節點的孩子數量 (cnt)。

外層迴圈枚舉每一個 RNA 位置 (1 到 m)。

內層迴圈將「沒有未處理孩子」的葉節點加入 Queue，由下往上 (Bottom-up) 推導至根節點。

轉移式概念：dp[父節點][父字元] += min(dp[子節點][子字元] + (父字元 != 子字元))。

最終只要取 dp[root][0~3] 中的最小值累加，即可得到該位置的最小距離。

## 解題方法思考
第一次做這題時，最大的盲點是「把整段 RNA 序列當成一個整體」。突破這個盲點後，這成了我第一次比較完整接觸並理解的「樹狀 DP (Tree DP)」題型。

在重新推導的過程中，我發現了許多可以優化的細節。例如，DFS/BFS 每一次其實只會處理固定的一個 RNA 位置，該位置從頭到尾都只是作為參數，不需要被 DP 陣列永久保存。因此可以將狀態從 dp[病毒][位置][字元] 壓縮成 dp[病毒][字元]。透過第三版的迭代寫法，我每次進入新的 RNA 位置時重新宣告一次 O(N) 的 DP 陣列，不僅邏輯清晰，也徹底避免了深度過深時的遞迴限制。

## 複雜度分析
以最終的第三份程式碼 (拓撲排序版) 為準：

### 時間複雜度：O(n * m)
每一個 RNA 位置 (共 m 個) 都需要對整棵樹 (共 n 個節點) 進行一次遍歷。在處理父子轉移時，只需枚舉固定的 4 x 4 = 16 種字元組合。常數極小，總時間複雜度為線性。

### 空間複雜度：O(n)
將 RNA 位置的維度從 DP 陣列中移除後，每次處理單一位置時，只需要宣告大小為 n 的 DP 狀態 dp[n+1][4]。加上儲存樹狀結構與字串的空間，整體空間複雜度完美控制在 O(n)。

## 學習心得
這題對我最大的幫助是讓我真正掌握了「樹狀 DP」的思考與降維方式。

一開始寫這題時，我對動態規劃還很不熟悉，甚至不知道如何定義狀態，只能先參考別人的做法。但在理解之後，我選擇在隔段時間後重新挑戰，自己一步步推導出狀態轉移方程式，最後甚至還能將遞迴優化成 BFS 拓撲排序的底層寫法。

這個過程讓我深刻體會到：學習演算法不只是把最佳解法背起來，而是要真正理解「為什麼要這樣設計狀態」。從一開始需要看答案，到後來能夠自己完成更進階的優化架構，這是我在動態規劃領域上一次非常具體的進步！
