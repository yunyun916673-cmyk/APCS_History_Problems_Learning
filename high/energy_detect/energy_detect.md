# 能量探測
## 題目意思
有一台探測機初始位置在二維平面的原點 (0, 0)。平面上的第一象限散佈著 n 個能量節點，給定每個能量節點的座標。
這台探測機的移動系統有限制：每次移動都只能往「右上方」前進。也就是說，如果探測機目前的位置在 (x, y)，它下一步移動到的目標位置 (x', y') 必須滿足 x' >= x 以及 y' >= y。
請計算出這台探測機在移動過程中，最多能夠收集到幾個能量節點（必須確實移動到節點所在的座標上才能進行收集）。

## 輸入格式
第一行包含一個整數 n，表示能量節點的總數量。
接下來有 n 行，每行包含兩個整數 x 與 y，表示第 i 個能量節點位於 (x, y) 座標。
保證不會有兩個能量節點出現在同一個位置。
## 輸出格式
請輸出一個整數，代表探測機最多可以收集到的能量節點數量。
## 範圍限制
20% 測資：1 <= n <= 100，1 <= x, y <= 100

30% 測資：1 <= n <= 1000，1 <= x, y <= 10000000

50% 測資：1 <= n <= 200000，1 <= x, y <= 10000000
# 能量探測
## 題目想法
初次接觸這道題目時，面對二維平面的條件限制，一開始沒有明確的思緒，甚至不知從何下手。後來透過查閱資料，
才認識了 LIS (最長遞增子序列) 這個強大的演算法概念，為解決這類問題開啟了全新的視野。

## 解題過程
學習到 LIS 的基本概念後，我順利實作出了第一份程式碼。當時使用的是雙層迴圈的動態規劃版本，雖然邏輯清晰，但面臨了 TLE（執行超時）的問題。
直到後來，我完整學習了 LIS 的進階優化技巧，在重新檢視這道題目時，便決定將其時間複雜度進行大幅度優化，利用維護 tails 陣列的方式實作出第二版 AC 程式碼。

## 解題方法思考
若嘗試直接在二維平面上處理每個點的關聯，情況會變得非常複雜且難以確保正確性。核心思維在於「降維打擊」：
首先對其中一個維度（X 座標）進行排序，如此一來，剩下的另一個維度（Y 座標）就轉變成了一維陣列。接著，只要對這個一維陣列求子序列即可。

值得注意的是，題目規定只要座標「不比原本小」即可前進，代表這是一個 LNDS（最長非遞減子序列）問題，允許數值重複。因此，在實作 tails 陣列（維護當前最長子序列的結尾元素）時，必須將傳統嚴格遞增所使用的 lower_bound 替換為 upper_bound，利用後方插入與替換的機制，就能輕易解開這道題目。

## 複雜度分析
#### 舊版寫法 (DP)：
使用了雙層迴圈嘗試更新每一個符合條件的狀態，時間複雜度為 O(N^2)。
在面對這題 N = 200,000 的大測資時會產生極大的運算量，導致 TLE。

#### 優化版寫法 (二元搜尋)：
對座標進行排序花費 O(N log N)，後續遍歷陣列並對 tails 陣列進行 upper_bound 搜尋，每次搜尋花費 O(log N)，總計遍歷 N 次。
整體時間複雜度降至 O(N log N)，空間複雜度為 O(N)，完美通過所有測資。

## 學習心得
這道題目是驗證 LIS 演算法與降維技巧非常經典的範例。
從一開始對演算法毫無頭緒，到後來能夠用 O(N^2) 暴力 DP 解出，再到最後可以流暢寫出 O(N log N) 的二元搜尋優化版本，
這兩份程式碼剛好見證了我在演算法學習路上的成長軌跡。
排序降維的思想與 upper_bound 的靈活運用，也讓我對處理非遞減子序列的核心機制有了更深刻的掌握。
