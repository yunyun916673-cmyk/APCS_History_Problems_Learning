# 邏輯電路

## 題目意思

給定一個由輸入端口、邏輯閘與輸出端口組成的邏輯電路。

每個輸入端口會提供 0 或 1 的訊號；邏輯閘共有 AND、OR、XOR、NOT 四種，依照連接線傳入的訊號進行運算。電路保證不存在迴路。

需要根據所有輸入訊號與電路的連接方式，計算每個輸出端口最後得到的 0 或 1，並找出從任一輸入端口傳遞到輸出端口時，最多會經過多少個邏輯閘，作為整個電路的最大延遲時間。

## 輸入格式

第一行輸入四個整數 p、q、r、m，分別表示輸入端口數量、邏輯閘數量、輸出端口數量，以及連接線數量。

第二行輸入 p 個二進制整數，表示各輸入端口的初始值。

第三行輸入 q 個整數，表示各邏輯閘的類型：
1 代表 AND、2 代表 OR、3 代表 XOR、4 代表 NOT。

接下來 m 行，每行輸入兩個整數 a、b，表示有一條連接線從端口 a 連向端口 b。

## 輸出格式

第一行輸出整個電路的最大延遲時間，也就是從輸入端口到輸出端口的路徑中，最多經過的邏輯閘數量。

第二行輸出 r 個二進制整數，依照輸出端口編號由小到大的順序，表示各輸出端口最後的訊號值。

# 邏輯電路

## 題目想法

一開始我看到這個題目的時候，還因為它的題目敘述而多研究了幾遍，不過我很快就把程式寫出來了。結果送出去之後，發現最後的測試資料竟然會導致 TLE。

所以我重新看了一遍自己的程式，發現問題是每一次遇到輸出端口時，我都會重新做一次完整的 DFS，導致很多已經計算過的邏輯閘又被重複計算。

因此我就開始想，能不能配合記憶化處理，把已經算過的結果記錄下來，這樣之後再次遇到相同的邏輯閘時，就可以直接使用之前的結果，降低整體的時間複雜度。

在加入 memory 和 SP 的過程中，我也發現原本的 DFS 只回傳一個數值並不夠，因為我除了需要知道這個邏輯閘最後輸出的 0 或 1 之外，還需要知道從這裡開始往前走，最多會經過多少個邏輯閘。

所以我最後把 DFS 的回傳值改成 pair，同時記錄訊號值和最大延遲時間。

## 解題過程

我先建立 P、Q、R、M，以及 PORTS 、 memory 和 SP。

其中 PORTS 用來儲存各個端口的訊號值，memory 用來記錄每個邏輯閘計算後的訊號結果，而 SP 則用來記錄從這個邏輯閘開始往前走時，最多會經過多少個邏輯閘。

接著，我把題目中所說的輸入端口寫成 input 函式，而題目中的 AND、OR、XOR、NOT 邏輯閘則分別寫成 AND、OR、XOR、NOT 函式，讓後面處理邏輯閘時比較方便。

最後先將整個電路的最大延遲時間 ANS 初始化為 0。

接下來進入 DFS。

因為我的 DFS 是從輸出端口往輸入端口的方向進行，所以我先判斷目前的位置是不是輸入端口。如果是的話，就直接回傳這個輸入端口的值，而經過的邏輯閘數量則是 0。

如果目前的位置是輸出端口，那麼我就直接繼續進行 DFS，讓它往前尋找與它連接的邏輯閘。

這樣做是因為這一題的電路可能會有一個邏輯閘連接到不同的端口，所以我從輸出端口反向尋找，可以一路找到真正影響這個輸出的邏輯閘。

剩下的情況就是目前的位置是邏輯閘。

因為我的 memory 和 SP 大小都只有 Q + 1，而邏輯閘的編號是從 P + 1 開始，所以我會把目前端口的編號減掉 P，轉換成 memory 和 SP 對應的位置。

接著，我先判斷這個邏輯閘是不是已經計算過。如果已經走過，而且 memory 和 SP 都已經更新完成，那麼我就直接回傳 memory 和 SP，不需要再次進行 DFS。

如果還沒有計算過，才繼續往前進行 DFS。

對於 NOT，我只需要取得它的一個輸入，計算出 NOT 的結果，再把最大延遲時間加一。

如果是 AND、OR 或 XOR，就需要取得兩個輸入，分別進行 DFS，再依照邏輯閘的種類計算結果。

而最大延遲時間則取兩條路徑中比較大的那一個，再加上一個目前的邏輯閘。

完成計算之後，再將結果存入 memory 和 SP，最後回傳這兩個值。

來到 main 之後，在完成初始化後，我會對每一個輸出端口分別進行一次 DFS。

針對 DFS 回傳的兩個數值，我分別更新 PORTS 和 ANS。PORTS 用來記錄這個輸出端口最後的訊號，而 ANS 則持續更新整個電路中的最大延遲時間。

最後再依照題目的輸出格式，先輸出最大延遲時間，再輸出每一個輸出端口的訊號值。

## 解題方法思考

一開始我使用單純的 DFS 來處理每一個輸出端口，但是後來發現如果每一個輸出端口都重新做一次完整的 DFS，就會造成大量重複計算。

因此我才想到使用記憶化，把已經計算過的邏輯閘結果保存下來。

這樣當不同的輸出端口最後都需要經過同一個邏輯閘時，第一次計算完成後，後面再次遇到這個邏輯閘就可以直接使用 memory 和 SP，不需要重新往前搜尋。

另外，在實作記憶化的時候，我也發現原本 DFS 只回傳一個值並不足以處理這題。因為我同時需要知道邏輯閘的輸出結果，以及從這個邏輯閘開始的最大延遲時間，所以最後使用 pair 一次回傳這兩個資訊。

這也讓我了解到，記憶化不只是把 DFS 的結果存起來而已，也需要先思考一個狀態到底需要保存哪些資訊，之後才能真正做到有效的重複利用。

## 複雜度分析

時間複雜度：

O(P + Q + R + M)

因為每一個邏輯閘在第一次被 DFS 計算時會將結果存進 memory 和 SP，之後再次遇到相同的邏輯閘時就可以直接使用已經計算好的結果，因此不會一直重複計算。

空間複雜度：

O(P + Q + R + M)

需要使用 PORTS 儲存各個端口的資料，SHIP 儲存連接關係，另外還需要使用 memory 和 SP 儲存每個邏輯閘的計算結果，因此整體空間複雜度與端口數量及連線數量有關。

## 學習心得

這一題讓我知道，我可以刻意做一個練習，讓自己習慣在 DFS 的時候思考記憶化處理。

以前看到 DFS 的時候，我比較容易直接想到把所有可能的路徑走過一次，但如果不同的路徑中會重複經過相同的狀態，就可能造成大量的重複計算。

這一題讓我實際遇到了這個問題，也讓我知道當 DFS 遇到 TLE 時，不一定要直接換掉整個演算法，有時候可以先觀察是不是有很多相同的狀態被重複計算，再利用記憶化把這些結果保存下來。

之後遇到其他 DFS 題目的時候，我也希望自己可以更加習慣去思考這件事情，看看能不能在 DFS 的過程中加入記憶化，避免重複計算，進一步降低整體的時間複雜度。
