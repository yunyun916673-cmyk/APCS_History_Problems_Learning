# 平緩步道

## 題目意思

在一個 n × n 的方格地圖中，每個格子都有一個高度。只能在上下左右相鄰的格子之間移動，而兩個相鄰格子的高度差絕對值就是該段步道的坡度。

從左上角的入口走到右下角的出口，需要找到一條**最平緩**的路徑，也就是讓路徑上所有相鄰格子的高度差之最大值最小。

如果有多條路徑都能達到最小的最大坡度，則要在這些路徑中找出**最短的路徑**。步道長度是移動的次數，因此經過的格子數會比步道長度多 1。

## 輸入格式

第一行輸入一個正整數 `n`。

接下來有 `n` 行，每行包含 `n` 個非負整數，依照由上到下、由左到右的順序表示每個方格的高度，數值之間以空白分隔。

入口固定為左上角，出口固定為右下角。

## 輸出格式

第一行輸出所有可行路徑中，最小的最大坡度。

第二行輸出在達到這個最小坡度的條件下，最短的步道長度。

## 範圍限制

* `2 <= n <= 300`
* 每個方格的高度為非負整數
* 高度 `<= 10^6`
* 只能在上下左右相鄰的方格之間移動
* 入口固定為左上角
* 出口固定為右下角
* 每筆測試資料執行時間限制：1 秒
* Python 執行時間限制：4 秒

# 平緩步道

## 題目想法

這題跟我之前做過的一道題目很類似，所以我第一眼看到題目的時候，就覺得這題應該可以使用二分搜尋。

不過題目還有另外一個條件，就是要輸出步數最少的路徑，而且這個步數最少的條件，是建立在最大坡度已經是最小的情況下。

所以我不能單純只找最短路徑，而是要先找出最小的最大坡度，再在這個條件下找最短路徑。

想到這裡之後，我就發現可以使用二分搜尋加上 BFS 來解決這題。

## 解題過程

在二分搜尋的 check 裡面，我從左上角的起點開始進行 BFS。

二分搜尋的參數是 ove，代表我現在假設整條路徑允許的最大坡度。

在 BFS 搜尋的過程中，我會檢查目前位置和下一個位置的高度差。

如果兩個位置的高度差超過 ove，就代表這個位置不能走，因此直接跳過。

如果沒有超過 ove，就可以把這個位置加入 BFS 的搜尋範圍。

最後看 BFS 能不能走到右下角的終點。

如果可以走到終點，就代表目前的 ove 是可行的，可以繼續往更小的坡度搜尋。

如果不能走到終點，就代表 ove 太小，需要把二分搜尋的範圍往更大的方向移動。

另外，因為 BFS 本身就是按照距離一層一層搜尋，所以在找到終點的時候，也可以同時知道目前這個坡度限制下的最小步數，並把它記錄下來回傳。

在 main 裡面初始化完成之後，我就進行二分搜尋，並記錄 check 所回傳的結果。

最後找到最小的最大坡度之後，再把對應的最短步數一起輸出。

## 解題方法思考

這題對我來說其實不算是一道完全陌生的題目，因為我之前已經做過類似的二分搜尋加 BFS 題目。

所以我第一眼看到題目的時候，就能很快聯想到二分搜尋，而不是從暴力搜尋所有路徑開始想。

這題的關鍵就是先固定一個最大坡度，然後利用 BFS 判斷在這個坡度限制下能不能從起點走到終點。

因為最大坡度越大，可以走的路就越多，所以這個判斷具有單調性，可以使用二分搜尋找出最小的可行值。

找到這個值之後，再利用 BFS 的搜尋層數取得在這個條件下的最短步數。

## 複雜度分析

時間複雜度：

O(n² log H)

每次 check 都需要進行一次 BFS，最多會搜尋整個 n × n 的方格，因此是 O(n²)。

二分搜尋需要 O(log H) 次 check，其中 H 是高度差的範圍，所以總時間複雜度為 O(n² log H)。

空間複雜度：

O(n²)

需要儲存整個方格，以及 BFS 使用的 visited 和 queue。
