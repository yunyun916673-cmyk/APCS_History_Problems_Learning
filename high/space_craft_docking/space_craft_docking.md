# 飛船停靠
## 題目意思
在星際聯邦的太空港中，每天都有許多飛船請求停靠。目前太空港總共有 K 個標準停機坪可以開放使用。

今日系統收到了 N 艘飛船的停靠申請，第 i 艘飛船需要佔用一個停機坪的時間段為 [Li, Ri]。一個停機坪在同一時間只能容納一艘飛船。
請特別注意，時間段的佔用是包含頭尾的。例如：時間段 [2, 5] 與時間段 [5, 10] 的兩艘飛船無法被安排在同一個停機坪，因為在時間點 5 兩者會發生重疊。

身為太空港的調度員，請問在最佳的安排下，最多能夠批准並成功停靠多少艘飛船？

## 輸入格式
第一行包含兩個正整數 N 與 K，分別代表飛船的申請數量以及太空港擁有的停機坪數量。
第二行包含 N 個非負整數，第 i 個數字是第 i 艘飛船申請的開始時間 Li。
第三行包含 N 個非負整數，第 i 個數字是第 i 艘飛船申請的結束時間 Ri。

## 輸出格式
請輸出一個整數，表示太空港最多可以容納的飛船數量。

## 範圍限制
0 <= Li <= Ri <= 10^8
K<=100

# 飛船停靠
## 題目想法
剛看到這題時，第一直覺聯想到類似「美食博覽會」的動態規劃（DP）題型。但進一步分析後發現不太對勁，因為這裡的停機坪（港口）是可以重複使用的，而且同一時間允許有 K 個活動重疊進行，這代表單純的 DP 無法輕易解決這個問題，必須轉換思考方向。
## 解題過程
一開始我陷入了一個盲點，一直糾結於如何將「時間區間」去對應「港口的編號」，但這個思路實作起來處處碰壁。後來我察覺到邏輯反了：由於港口數量（K）相對較少，而區間數量（N）很大，應該要是讓「港口」來對應「區間」。
我們不需要把所有區間的編號都塞進去，只需要記錄每個港口「上一次被使用的結束時間」即可。只要當前飛船的開始時間（Left）大於某個港口上一次的結束時間，就代表該港口有空檔可以使用。
## 解題方法思考
這題的核心是貪心演算法 (Greedy) 搭配平衡二元搜尋樹 (multiset)：
 * 排序策略：為了盡可能容納最多飛船，必須依照區間的「結束時間 (Right)」由小到大進行排序，確保提早結束的飛船優先停靠，把後續的時間空出來。
 * 狀態初始化：將 K 個港口的上一次使用結束時間都設為 -1 並放入 multiset 中（設為 -1 是為了兼容從時間 0 開始的測資）。
 * 分配港口 (Best Fit)：從頭遍歷排序好的區間，針對每一個區間的開始時間（Left），在 multiset 中使用 upper_bound 找出第一個大於開始時間的迭代器，接著將該迭代器往前退一格（--it），就能精準找到「小於等於當前開始時間且最晚結束」的港口。
 * 狀態更新：找到適合的港口後，將該港口舊的結束時間從 multiset 中刪除，並把當前飛船的結束時間（Right）新增進去，最後將成功停靠的計數器加一。
## 複雜度分析
### 時間複雜度：
   對所有飛船區間進行排序需要 O(N log N)。
   接著遍歷 N 個區間，每次在大小為 K 的 multiset 內執行 upper_bound、erase 與 insert 的操作，單次為 O(log K)，總共需要 O(N log K)。
   整體時間複雜度為 O(N log N + N log K)，能夠輕鬆通過 N=100,000 的大測資。
### 空間複雜度：
   需要一個大小為 N 的陣列來儲存區間，以及一個最大長度為 K 的 multiset 來維護機台狀態。整體空間複雜度為 O(N + K)。
## 學習心得
這是一題非常典型的「吃電波」演算法題。如果沒有想對方向（例如卡在按照開始時間排序，或是陷入窮舉編號的泥沼），就會一直卡住寫不出來。然而，只要演算法的靈感一閃而過——想到利用「結束時間排序」加上「維護機台結束狀態」的貪心策略，這題瞬間就變成一道秒殺題。
解這題不需要維護繁雜瑣碎的細節，缺的只是一個關鍵的演算法靈感。這種一擊必殺的解題體驗非常有成就感！
