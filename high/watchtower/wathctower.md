# 瞭望臺
## 題目意思
老舊港口邊停靠著一排共 N 艘貨船，從左到右編號為 1 到 N。第 i 艘船的船身高度為 H[i]，船員可以站在高度為 P[i] 的瞭望臺上向前（往編號較小的方向）眺望。

當第 i 艘船上的船員站在瞭望臺上時，他們的視線最高可達高度 H[i] + P[i]。若在編號 k（k 小於 i）與 i 之間，存在任何一艘船的船身高度大於或等於 H[i] + P[i]，視線就會被該船擋住；反之，在 k 與 i 之間所有船隻的船身高度都嚴格小於 H[i] + P[i] 的情況下，視線即可不受遮蔽地抵達船 k。

此外，在港口最左側（編號 0 的位置）有一座極高的燈塔，高度視為無限大，能擋住所有超出範圍的視線。請計算出所有船隻（1 到 N）各自能不受遮蔽看到的、位於其左側且高度嚴格大於 H[i] + P[i] 的最近障礙船（或燈塔）之間，夾著多少艘其他船隻，並將所有船隻的這個數量加總輸出。

## 輸入格式
第一行包含一個正整數 N，代表貨船數量。
第二行包含 N 個正整數，依序代表 H[1], H[2], ..., H[N]。
第三行包含 N 個正整數，依序代表 P[1], P[2], ..., P[N]。

## 輸出格式
輸出一行整數，代表所有船隻統計結果的總和。

## 範圍限制
1 <= N <= 200000

1 <= H[i], P[i] <= 1000000000

# 瞭望臺
## 題目想法
在排隊序列中，每個人都有自己的身高 H[i] 與墊高高度 P[i]，視線高度上限為 H[i] + P[i]。我們要找到左側最近且高度嚴格大於 H[i] + P[i] 的人，計算兩者之間夾著多少人，並把所有人的這個數量加總起來。直覺上若對每個人都往左掃描，遇到太高的人或超出範圍就會停下，但直接暴力往左走會超時，因此需要用單調結構配合二分搜尋來加速查詢左側第一個嚴格大於 H[i] + P[i] 的位置。

## 解題過程
一開始思考這題怎麼快速找到左側嚴格大於 H[i] + P[i] 的人，發現維護的候選序列在高度上是單調遞減的。透過在陣列最前端放一個極大值哨兵（索引 0 設為極大高度），就能確保任何查詢都能在序列中找到合法的左邊界。

在實作上，我嘗試了兩種寫法：一種是手寫二分搜在單調遞減的索引序列 temp 中找符合條件的最右邊位置；另一種是使用 upper_bound 搭配自訂比較子來尋找分界點再往回退一步。在處理完第 i 個位置的統計後，再把 temp 中高度小於等於 H[i] 的索引彈出，維持單調性並將 i 推入。

## 解題方法思考
這題的核心在於把「往左找第一個高度嚴格大於 H[i] + P[i] 的對象」轉化為在單調遞減序列中的查詢問題。由於我們維護的索引對應高度是嚴格遞減的，查詢目標值 cur = H[i] + P[i] 時，可以直接在單調序列上做二分搜定位，算出 i - 目標索引 - 1 就是中間隔著的人數。

在寫法選擇上，手寫二分搜雖然程式碼稍微長一點，但邊界條件與比較邏輯完全掌握在自己手裡，不容易因為迭代器移動或自訂比較子的嚴格弱序細節出錯；若使用 upper_bound，則要特別留意邊界與比較方向是否與遞減序列一致。

## 複雜度分析
### 時間複雜度：O(N log N)。
共有 N 個元素，每個元素最多進出單調序列一次，且每次查詢會在大小不超過 N 的單調序列上進行二分搜尋，整體時間為 O(N log N)。

### 空間複雜度：O(N)。
需要陣列儲存高度與額外高度，以及單調序列存放索引，空間量級為 O(N)。

## 學習心得
這題讓我更熟悉把「單調棧」與「二分搜尋」結合起來處理區間或左側邊界查詢的思路，也體會到哨兵值在簡化邊界判斷上的實用性。
