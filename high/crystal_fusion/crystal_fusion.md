# 水晶融合
## 題目意思
魔法師面前有一排共 n (n<=100) 顆能量水晶，每顆水晶都有特定的能量值。魔法師每次可以選擇兩顆相鄰的水晶進行融合。
假設選取的兩顆水晶能量值分別為 u 與 v，則融合這兩顆水晶需要消耗 |u-v| 點的魔力（即兩者能量差的絕對值）。融合完成後，會形成一顆新的水晶，其能量值為 u + v。
請問魔法師將這 n 顆水晶逐步融合，直到最後只剩下一顆水晶為止，最少需要消耗多少點的總魔力？
## 輸入格式
第一行包含一個正整數 n，代表能量水晶的數量。
第二行包含 n 個整數 a_1, a_2, a_3, ... , a_n，代表一開始由左至右每顆水晶的能量值。數字之間以一個空白字元隔開。
## 輸出格式
請輸出一個整數，代表將所有水晶融合成一顆所花費的最小魔力總和。

# 水晶融合
## 題目想法
一開始看到題目，發現測資範圍 N 非常小（N <= 100），這為解題方法提供了很大的彈性。
起初，我直覺想使用「貪心演算法 (Greedy)」，每次都挑選當前絕對值差最小的相鄰水晶進行融合。但後來仔細思考發現，這種做法無法保證總消耗最小，因為每次融合後數值會合併，這會直接影響到後續的選擇與計算。這也解釋了為什麼這題的 N 會設得這麼小，暗示我們必須放棄貪心，改用動態規劃 (DP) 進行全局窮舉。
## 解題過程
確認貪心法失效後，我轉向使用「區間 DP (Interval DP)」。因為題目要求相鄰區間的合併，可以將問題拆解為「合併左半區間」加上「合併右半區間」，最後再將兩者合併的過程。
為了解決合併時需要快速知道該區間的總能量值，我搭配了「前綴和 (Prefix Sum)」來進行 O(1) 的查詢，避免每次都重新計算區間和，進而加速整個 DP 的推導。
## 解題方法思考
 * 狀態定義：建立一個二維 DP 陣列 dp[i][j]，第一維 i 代表區間左邊界，第二維 j 代表區間右邊界。陣列中儲存的值為「將連續區間 [i, j] 融合為一顆水晶所需的最小能量消耗」。
 * 初始狀態：當區間長度為 1 時（即 i == j），因為不需要進行任何融合，所以最小消耗為 0，即 dp[i][i] = 0。
 * 狀態轉移：使用三個包在一起的迴圈來實作區間 DP：
   * 最外層迴圈枚舉「區間長度 (len)」，從長度 2 開始直到 N。
   * 第二層迴圈枚舉「區間左起點 (i)」，並由此推算出右終點 j = i + len - 1。
   * 第三層迴圈枚舉「切點 (k)」，範圍從 i 到 j-1（左半邊包含切點 k，右半邊不包含）。
 * 轉移方程式：我們將區間分成左半邊與右半邊。最後一步融合的消耗，會是左半邊的總能量與右半邊總能量的差值絕對值（透過前綴和 left 與 right 快速求出）。因此：
   dp[i][j] = min(dp[i][j], dp[i][k] + dp[k+1][j] + abs(left - right))
 * 最後，答案即為 dp[0][N-1]。
## 複雜度分析
### 時間複雜度：使用了三層迴圈（枚舉長度、起點、切點），因此時間複雜度為 O(N^3)。對於 N <= 100 來說，立方複雜度完全可以輕鬆通過。
### 空間複雜度：建立了一個二維 DP 陣列 O(N^2)，以及一個前綴和陣列 O(N)，總體空間複雜度為 O(N^2)。
## 學習心得
這題給我很大的一個啟發：因為平常解題建立了「一定要盡量優化再優化」的習慣，反而讓我在一開始思考時卡住了。但有時候面對 N 很小的題目，其實就應該放開這個束縛，直接使用三層迴圈去處理。
除了解法本身是「區間 DP」在狀態定義上稍微抽象一點之外，只要把邏輯理清，這題本質上就是用動態規劃框架來進行暴力窮舉。學會根據資料範圍選擇最直接、不需想太多的解法，也是一種很重要的競技程式策略！
