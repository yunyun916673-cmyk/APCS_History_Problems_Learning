# 鋪地磚
## 題目意思
你是一個室內設計師，負責鋪設一條寬度為 2 單位、長度為 N 單位的長方形走廊。你可以使用以下兩種形狀的地磚，且數量無限：
 * 面積為 1 單位的「正方形地磚」(1x1)。
 * 面積為 3 單位的「L 型地磚」(佔據 2x2 空間但缺一個 1x1 的角)。
請問要將大小為 2 x N 的走廊完全鋪滿，總共有多少種不同的排列方式？
## 輸入格式
輸入的第一行會有一個正整數 T，代表共有 T 筆測試資料。
接下來的 T 行，每行包含一個正整數 N，代表每次要求鋪設的走廊長度。
## 輸出格式
對於每一筆測試資料 N，請輸出一行，代表將 2 x N 的走廊完全鋪滿的方法總數。
## 範圍限制
 * T 為正整數
 * 1 <= N <= 40
 * 輸出結果保證小於 10的18次方 (10^18)，請使用 64-bit 整數型態 (如 long long)。


# 鋪地磚
## 題目想法
這一題很明顯是一個動態規劃 (Dynamic Programming) 求方法數的問題。雖然看似是常見的磁磚鋪設題型，但因為多了一種「佔據 3 單位面積的 L 型地磚」，導致許多組合的細節藏在其中，思考狀態轉移時需要格外仔細，確保每種拼法不遺漏且不重複。
## 解題過程
為了防止計算時發生陣列越界的問題，我先宣告一個大小為 41 的 dp 陣列（用來儲存長度 0 到 40 的方法數），並手動將邊界條件 dp[0]、dp[1] 和 dp[2] 初始化。
接著利用迴圈從長度 3 開始往後計算到 40。考慮到可能會有多筆測資 (T)，我採用了「預先建表 (Precomputation)」的策略，把所有可能的長度答案先算好，之後讀取每筆輸入 N 時，就能直接輸出結果，大幅提升執行效率。
## 解題方法思考
本題的核心在於狀態轉移方程式：
dp[i] = dp[i-1] + dp[i-2] * 4 + dp[i-3] * 2
可以將鋪設到長度 i 的方法分為三種情況：
 * 補滿最後 2x1 空間 (dp[i-1])：不使用任何 L 型，單純在最右側填上兩個 1x1 地磚。
 * 補滿最後 2x2 空間 (dp[i-2] * 4)：在最右側的 2x2 空間中，使用 L 型與 1x1 地磚進行組合。扣除掉全用 1x1 的情況（因為已經包含在第一種情況裡），剛好剩下 4 種不重複的拼法。
 * 補滿最後 2x3 空間 (dp[i-3] * 2)：使用兩個 L 型地磚，剛好可以完美拼出一個 2x3 的矩形，這樣的特殊拼法共有 2 種。
將這三種獨立的情況相加，就能得到推導至長度 i 的總方法數。
## 複雜度分析
### 時間複雜度：O(N + T)，其中 N 為最大長度 (40)，T 為測資筆數。預先建表只需 O(N) 的時間跑一次迴圈，後續每筆查詢都只需 O(1) 的時間，效率極高。
### 空間複雜度：O(N)，只需宣告一個長度為 41 的一維 long long 陣列來儲存 DP 狀態。
## 學習心得
這題整體架構看起來雖然簡單，但屬於「必須做出正確的狀態規劃，且要小心各種細節」的題型。尤其是 DP 初始化的部分非常容易踩坑，例如 dp[0] 必須設為 1，代表「剛好用積木塞滿空間也是一種合法的方法」。我一開始就在初始化的細節栽了跟頭，這也提醒了我，未來在設計動態規劃時，不僅轉移式要嚴謹，初始條件的定義也同樣是決定成敗的關鍵。
