# 空間傳送
## 題目意思
有一條長度為 $m$ 的星際航線，你的起點在座標 $0$，目標是抵達座標 $m$ 的終點站。
航線上設有 $n$ 個單向的空間傳送通道，每個通道都有其運作的起點與終點範圍。

搭乘傳送通道的規則如下：
1. 假設你目前位在座標 $x$，你可以進入任何「涵蓋座標 $x$」的通道（即通道的起點 $<= x$，且通道的終點 $> x$）。
2. 一旦進入通道，就必定會被直接傳送到該通道的終點座標才能離開。
3. 不能在同一個座標同時進入並馬上離開（即進入的座標點必須嚴格小於終點座標）。
4. 最一開始你位於座標 $0$，最後一次搭乘的通道終點必須剛好是座標 $m$。

請問總共有多少種不同的通道搭乘順序組合可以順利抵達座標 $m$？由於方法數可能非常大，請輸出總組合數對 $p$ 取模（mod）後的結果。

## 輸入格式
第一行包含三個正整數 $n$、$m$、$p$，分別代表有 $n$ 個傳送通道、目標終點座標為 $m$，以及答案要取模的整數 $p$。
第二行包含 $n$ 個整數，分別代表每一個傳送通道的起點座標。
第三行包含 $n$ 個整數，分別代表每一個傳送通道的終點座標。

## 輸出格式
輸出一個整數，代表抵達終點的傳送通道搭乘方式總數，並對 $p$ 取餘數。

## 範圍限制
- $1 <= n <= 2 × 10^5$
- $1 <= m <= 10^9$
- $1 <= p <= 10^9 + 9$

# 空間傳送

## 題目想法
剛看到這道題目時，因為是要求「總共有多少種方式到達終點」，我的第一直覺是使用**動態規劃（Dynamic Programming）**。最初的想法是試圖去記錄「到達特定路線」的方法數，但在推導狀態轉移的過程中，發現好像必須牽扯到二分搜尋，導致整體的邏輯變得非常複雜。

最大的痛點在於座標範圍高達 $10^9$，這讓直觀的「點對應區間」陣列操作變得不可能。直到我去查閱相關資料，才發現了一項關鍵技術——**座標壓縮（離散化）**。這是我以前可能無意間用過，但從未正式認識的技巧。理解這個概念後，整道題目瞬間豁然開朗，從複雜的搜尋問題回歸到簡單的區間求和問題。

## 解題過程
引入「座標壓縮」後，我將原本分散且巨大的座標值（最大至 $10^9$），透過建立對照表的方式，壓縮到一段連續且緊湊的陣列範圍內。這樣一來，原本因為空間限制而無法實作的區間查詢，就變得完全可行了。

在實作上，我寫了兩個版本：**樹狀陣列（BIT）** 與 **線段樹（Segment Tree）**。兩者都非常適合處理這題，核心操作皆為「記錄有多少種方法可以到達某個點」，並透過資料結構快速查詢「一段區間內的總方法數」。

## 解題方法思考
我使用了以下幾個關鍵的資料結構與變數來建構解法：
- `org`：用來儲存所有的路線區間（起點與終點）。
- `cursor` (set)：用來收集所有出現過的座標點，包含起點、終點以及 0 和 m，並自動排序去重。
- `trans` (unordered_map)：作為座標壓縮的對照表，將大座標映射為連續的小 index。

**核心邏輯如下：**
1. **初始化與對照表建立**：將起點、終點放入 `cursor` 中，並透過迴圈給予每一個獨立座標一個連續的編號，記錄在 `trans` 裡面。
2. **區間排序**：將 `org` 內的所有區間依照「終點位置」從小到大排序，確保狀態轉移的順序正確（從前向後推進）。
3. **區間查詢與單點更新**：走訪每一條通道，當我們進入某條路線時，可以從「起點」到「終點前一個座標」的任何一個點上車。因此，我們利用 BIT 或線段樹，查詢區間 `[left, right-1]` 的總方法數（不包含 right 是因為題目規定不能在同一點同時上下車）。
4. **狀態推移**：將查詢到的區間方法數總和，加總更新到該路線的「終點」上。
5. 最後，查詢終點 $m$ 的方法數即可得到答案。

## 複雜度分析
### 時間複雜度：
  - 座標壓縮（使用 `set` 與 `unordered_map`）：$O(N log N)$。
  - 排序通道區間：$O(N log N)$。
  - 查詢與更新（BIT 或 線段樹）：對於 $N$ 條通道，每次操作需要 $O(log K)$（其中 $K$ 為離散化後的座標總數，最大約為 $2N$），故這部分為 $O(N log N)$。
  - **總時間複雜度**：$O(N log N)$，足以順利通過所有測資。
### 空間複雜度：
離散化後的座標數量最多約為 $2N+2$，不論是開 BIT 陣列（$O(N)$）或是線段樹陣列（$O(4N)$），**總空間複雜度**皆為 $O(N)$。

## 學習心得
這題帶給我最大的收穫，就是正式將**「座標壓縮（離散化）」**這個概念收編進我的演算法工具箱中。

以前碰到數值範圍極大（如 $10^9$）的題目，總會覺得無法使用陣列或區間資料結構來解；但現在我學會了：只要「實際出現的點數量」在可以接受的範圍內，就能透過建立對照表將問題簡化。這次成功結合了座標壓縮與區間資料結構（BIT/線段樹），讓我在面對這類題目時多了一個強大且實用的思考維度！
