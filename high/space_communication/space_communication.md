# 星際通訊
## 題目意思
在浩瀚的星際聯邦中，分佈著 n 個星際中繼站，編號依序為 0 到 n-1。這些中繼站由 n-1 條量子光纖通道相互連接，構成了一個結構簡單且全域連通的樹狀通訊網絡。
聯邦總部為了進行極限頻寬壓力測試，決定對關鍵節點進行檢測。定義「最長通訊路徑」為一條由多個不同中繼站組成的路徑，且其長度（經過的通道總數）達到整個網絡中的最大值（全網最大距離）。
由於這樣的最長路徑可能有多條，總部希望找出所有「位於至少一條最長通訊路徑上」的中繼站，以便加強系統維護。請你編寫一個程式，找出所有符合條件的中繼站編號。
## 輸入格式
第一行包含一個整數 $n$，表示中繼站的總數。接下來 n-1 行，每行包含兩個整數 u 和 v，表示編號為 u 和 v 的中繼站之間存在一條量子光纖通道。
## 輸出格式
輸出包含若干行，每行包含一個整數，代表某個位於最長通訊路徑上的中繼站編號。
為了確保輸出結果規範，請將所有符合條件的中繼站編號由小到大依序輸出，每個編號輸出一次。範圍限制1 <= n <= 2 * 10^5

# 星際通訊
## 題目想法
這題的核心本質在於尋找「樹的直徑（Tree Diameter）」。根據圖論中的經典性質，從樹上任意一點出發，透過廣度優先搜尋（BFS）或深度優先搜尋（DFS）所找到的最遠點，必定是整棵樹直徑的其中一個端點。
因此，只要先從任意點（例如編號 0）出發做第一次 DFS 找到端點一，再從端點一出發做第二次 DFS 就能找到直徑的另一個端點。
既然已經有了兩個直徑端點，要找出所有位於任一條最長路徑上的節點，最直覺的想法就是分別從兩個端點出發，找出所有符合距離條件的節點。
雖然理論上也能透過記錄每個節點到兩端點的距離和是否等於直徑長度來篩選，但透過兩次 DFS 分別回溯並標記路徑，最後將結果合併並去重，寫法直觀且程式碼結構相當清晰。
## 解題過程
第一次 DFS：從根節點（編號 0）出發，遍歷整棵樹以尋找距離最遠的節點，該節點即為直徑的第一個端點 (root1)。
第二次 DFS：從 root1 出發，再次遍歷整棵樹尋找距離最遠的節點，得到直徑的第二個端點 (root2)。
第三與第四次 DFS（路徑標記）：分別從 root1 和 root2 出發向下遞迴，當遞迴深度等於樹的直徑長度時，將路徑上的節點全部收集起來。
整理與輸出：將收集到的所有節點編號進行排序（sort）與去重（unique），確保輸出的節點編號不重複且由小到大依序排列。
## 解題方法思考
樹的直徑性質：掌握「樹中任意點最遠點必為直徑端點」的定理，能將原本複雜的全域路徑搜尋簡化為兩次基礎的 DFS。
常數優化與實作取捨：雖然可以透過計算每個節點到兩端點的距離和（dist(root1, u) + dist(root2, u) == diameter）來判定，
但在本題的數據規模下，直接利用三次/四次 DFS 進行路徑收集與去重已經足夠高效，且實作上更不容易出錯。
## 複雜度分析
### 時間複雜度：O(N)。
樹的走訪每個節點與邊只會被訪問常數次，總共進行了幾次 DFS，其時間與節點數 N 成線性關係。以 N = 2*10^5 來說，能在毫秒級別內輕鬆通過。
### 空間複雜度：O(N)。
主要用來儲存鄰接串列（Adjacency List）ship、遞迴呼叫堆疊（Call Stack）以及儲存路徑節點的 vector。
## 學習心得
這題讓我更加深刻理解樹的直徑在實際演習題型中的應用。
利用兩次 DFS 定位直徑端點是圖論題目的標準操作，而後續要找出所有在直徑上的點時，透過從兩端點出發的收集與集合合併（去重），是一種非常直觀且好寫的思維方式。
雖然有更嚴謹的距離和判定法，但透過這題也學會了在時間允許的範圍內，選擇實作風險低、邏輯清晰的寫法往往是競賽中拿分的關鍵。
