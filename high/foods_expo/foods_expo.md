# 美食博覽會
## 題目意思
星際城市正在舉辦盛大的「美食博覽會」，共有 n 個美食攤位排成一條筆直的長街。每個攤位只販售一種特定種類的美食（以非負整數表示）。

現在有一個知名美食網紅團隊，團隊中共有 k 名評論員來到博覽會。每位評論員都可以選擇從任意一個攤位開始，沿著街道依序造訪相鄰的攤位並品嚐美食。但是，評論員們對重複的食物感到厭倦，因此每位評論員在自己這趟連續造訪的過程中，只要遇到這趟行程中曾經吃過的美食品項，就會立刻停止試吃並結束行程。

為了產出最豐富的報導，團隊希望透過妥善規劃每位評論員的起點與路線，讓所有人造訪過的「攤位總數」加總起來最多（若同一個攤位被多位評論員重複造訪，總數中只計算一次）。請計算出這 k 位評論員最多總共能造訪幾個不同的攤位。

## 輸入格式
第一行包含兩個整數 n 與 k，分別表示攤位總數與評論員人數。
第二行包含 n 個以空白分隔的整數，代表依序排成一列的攤位所販售的美食品項編號。

## 輸出格式
輸出一個整數，表示評論員團隊最多能造訪的攤位總數。

## 範圍限制
1 <= n <= 10^6

1 <= k <= 20

n * k <= 5 * 10^6

攤位的美食品項編號皆為小於 10^5 的非負整數。

第1子題組 (50分)：k = 1。

第2子題組 (50分)：無額外限制。

# 美食博覽會

## 題目想法

最初的想法是先求出所有以 i 為「起點」的最長不重複子序列（拼圖），然後再利用動態規劃（DP）去求「只使用前 i 個元素，總共拼 j 次」的最大值。
但順著這個直覺思考，在狀態轉移時遇到很大的困難，一直無法成功建構出正確的模型。後來才意識到，必須把思路倒過來：與其求右端點，不如求左端點。

## 解題過程

這道題目我想了很久，一開始因為起點與終點的視角問題卡關，遲遲無法成功做出來。後來決定先參考正確的解題思路，才恍然大悟。理解概念後，我沒有直接抄寫，而是靠著自己重新思考與推導，成功把完整的程式碼實作出來。過程中最大的突破就是放棄尋找向右延伸的極限，改為尋找向左延伸的極限。

## 解題方法思考

這題的核心解法可以分為「預處理」與「動態規劃」兩個階段：
### 1. 預處理：
不找起點，而是以每個位置 i 為「終點」，計算它最長可以向左延伸到什麼程度（左端點 L[i]）。這樣只需要透過記錄數字最後出現的位置，
用一個 O(N) 的迴圈就能一路從最前面遍歷到最後，輕鬆完成記憶化。
### 2. 動態規劃轉移：
定義 DP 狀態為當前使用第 i 次拼拼圖的機會時，前 j 個位置能填滿的最大數值。對於第 j 個位置，我們有兩種選擇：
  #### (1)完全放棄填寫第 j 個位置：
  直接繼承前一個位置的最佳結果，即 dp[i][j-1]。
  #### (2)選擇以 j 為結尾的這塊拼圖：
  從這塊拼圖的最左端再往左退一格（即 L[j]-1），拿少用一次機會時的片面最大化結果，加上當前這塊拼圖的長度，即 dp[i-1][L[j]-1] + (j - L[j] + 1)。
最後取這兩者的最大值即可完成狀態轉移。

## 複雜度分析

### 時間複雜度：
預處理左端點需要 O(N)，動態規劃的狀態轉移需要遍歷 k 次機會與 n 個位置，
時間為 O(NK)，足以通過 5*10^6 的數據範圍限制。
### 空間複雜度：
原先的二維 DP 會需要 O(NK) 的空間，但我使用了「滾動陣列」的技巧，交替使用兩條長度為 N 的陣列，將空間複雜度降維至 O(N$。

## 學習心得

這次解題最大的收穫是體會到「轉換視角」的重要性。有時候順著直覺走（以某點為起點向右看）反而會讓後續的 DP 轉移變得異常複雜。
但只要稍微反直覺一點（以某點為終點向左看），整個思路就瞬間豁然開朗。
此外，雖然這次是看了提示才解出來，但透過親自把思路倒過來重寫一遍，反而將這個「計算左端點」的 DP 技巧深深烙印在腦海裡，是一次非常扎實的學習經驗。
