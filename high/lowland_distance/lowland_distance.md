# 低地距離

## 題意整理

給定一個長度為 2n 的數列，其中 1 到 n 每個數字都恰好出現兩次。

對於每個數字 i，考慮它第一次與第二次出現的位置，計算這兩個位置之間有多少個數字嚴格小於 i，稱為 i 的低窪值。

請計算所有 1 到 n 的低窪值總和。

## 輸入格式

* 第一行輸入一個整數 n。
* 第二行輸入 2n 個整數，保證 1 到 n 每個數字皆恰好出現兩次。

## 輸出格式

輸出一個整數，表示所有數字低窪值的總和。 

# 低地距離

## 題目想法

一開始看到這一題的時候，我很快就寫出了一個解法，結果最後才發現題目的限制是 N 最多可以到 10 的 5 次方，原本的做法時間複雜度太高，最後一定會 TLE。

當時我左思右想，就是想不到有什麼方法可以把時間複雜度降下來。後來去查了一些資料，也問了一些問題，才知道這一題其實可以利用 BIT 來處理，只不過要搭配由小到大的處理順序，才能有效率地完成這一題。

## 解題過程

我先建立 N、BIT 陣列，並且實作好 lowbit 、 update 、 query 等 BIT 會用到的函式。接著先記錄每一個數字第一次和第二次出現的位置，方便之後查詢。

在初始化完成之後，我就按照數值由小到大的順序開始處理。因為數值最小的元素，不管它出現在哪兩個位置，都不可能有比它更小的數字，所以它的低窪值一定是 0。

因此在每一次迴圈中，我先利用 query(right) - query(left)，查詢目前 left 到 right 之間已經被加入 BIT 的位置數量。由於我是按照數值由小到大的順序處理，所以 BIT 中維護的都只會是比目前數字還小的數字，因此查詢到的結果就是目前數字的低窪值，可以直接累加到答案中。

完成查詢之後，再把目前數字的兩個位置利用 update 加入 BIT。這樣下一個比較大的數字在查詢時，就能正確把目前這個數字也計算進去，不會產生誤差。

最後輸出累加完成的答案即可。

## 解題方法思考

如果直接暴力去計算每一個數字中間有多少個比它小的數字，雖然很容易實作，但是時間複雜度會是 O(n²)，在 N 最多到 10 的 5 次方時一定無法通過。

這一題真正困難的地方，就是必須想辦法把時間複雜度降到 O(n log n)。而 BIT 剛好可以快速維護已經處理過的位置，再搭配由小到大的處理順序，就能保證 BIT 中永遠只會存在比目前數字小的元素，因此每一次查詢都能直接得到答案。

我覺得這題最大的重點不是 BIT 本身，而是想到要按照數值由小到大的順序處理，才能讓整個 BIT 的維護方式成立。

## 複雜度分析

### 時間複雜度：

O(n log n)

每個數字都會進行一次區間查詢，以及兩次 BIT 更新，每次操作都是 O(log n)，因此總時間複雜度為 O(n log n)。

### 空間複雜度：

O(n)

需要額外儲存每個數字出現的位置以及 BIT 陣列，因此空間複雜度為 O(n)。

## 學習心得

這一題如果只想拿到前面的部分分，其實並不困難，直接暴力就可以完成。但是剩下的 40% 就必須把時間複雜度從平方降到 O(n log n)，否則一定會超時。

一開始我完全沒有想到可以用 BIT 來解這一題，後來查資料之後才發現，除了 BIT 本身之外，更重要的是要搭配由小到大的處理順序，才能讓整個做法成立。這也讓我學到，很多資料結構都不是單獨使用，而是需要配合適當的處理順序，才能真正發揮效果。這題也讓我對 BIT 的應用有了更深的理解，不再只會把它拿來做最基本的區間加總。
