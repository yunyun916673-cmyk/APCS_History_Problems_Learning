# 量子網格
## 題目意思
在未來的星際運算中心，核心伺服器由 n * n 的「量子網格」所構成。透過探測器掃描，每個網格區塊都擁有特定的「能量位階」（數值）。

受限於量子互斥原理，相鄰的網格（擁有共同邊的區塊）絕對不會出現相同的能量位階。

為了防止伺服器過熱引發核心熔毀，工程師必須在網格中部署最多 m 個「冷卻節點」。

能量流動的規則是：只能由能量位階「較高」的網格，流向相鄰且能量位階「較低」的網格，每跨越一個網格需要花費 1 單位的傳輸時間。

若該網格建有冷卻節點，則散熱傳輸時間為 0。沒有冷卻節點的網格，其散熱時間等於能量流動到任意一個冷卻節點的最短傳輸時間。

系統安全性限制：為了避免冷卻液逆流引發量子共振，任兩個「冷卻節點」之間，絕對不能存在合法的能量流動路徑（也就是能量不能從一個冷卻節點一路流向另一個冷卻節點）。

請在最多部署 m 個冷卻節點的限制下，找出能讓所有網格中「最長的散熱傳輸時間」降到最低的最佳配置，並輸出這個最小化的最大時間。如果即使部署了 m 個節點，仍有網格的能量無法傳遞到任何冷卻節點，請輸出 Impossible。

## 輸入格式
第一行的整數 t (0 < t < 50) 表示有幾筆測試資料，接著是 t 筆測資。
每一筆測資的第一行有兩個整數 n (0 < n < 500) 和 m (0 < m < 1000)，分別表示量子網格為 n * n 大小，且最多允許部署 m 個冷卻節點。
接著有 n 行，每行有 n 個數字表示網格區塊的能量位階 d (0 < d < 2147483648)。

## 輸出格式
每筆測資輸出 1 行，共輸出 t 行。
若需要超過 m 個冷卻節點才能讓所有網格區塊順利散熱，請輸出 Impossible；否則請輸出在最佳配置下（讓最慢散熱的區塊花費時間最短），該區塊所需的傳輸時間。

## 範圍限制
0 < t < 50

0 < n < 500

0 < m < 1000

網格能量位階 d 介於 0 < d < 2147483648

# 量子網格
## 題目想法
這題本身並不需要用到非常艱深的演算法，真正的難點在於「題意轉換」。題目將核心邏輯包裝在網格地圖與能量流動的情境中，必須看透這層表象，將二維網格抽象化為一張「有向無環圖 (DAG)」，才能找出對應的圖論與動態規劃解法。

## 解題過程
地圖轉換與建圖：將二維網格地圖轉換為節點地圖。遍歷每個位置，若相鄰位置的數值較低，則建立一條單向邊，記錄該位置的能量能流向哪些周圍節點（即圖的相鄰串列 ship）。

尋找必備冷卻點：在所有的單向連通塊中，找出所有的「葉節點」（也就是出分度為 0、沒有任何相鄰較低點、ship 大小為 0 的位置）。在這些位置加入冷卻器，並檢查所需總數是否超過 M，若超過則輸出 Impossible。

動態規劃 (DP) 求解：建立一個 DP 陣列來儲存每個節點到達冷卻器的最短距離（等價於流動時間）。為了確保狀態轉移的正確性，將所有位置依照數值「從低到高」進行排序。

狀態轉移：依照排序結果處理每個位置，保證在計算當前位置時，它能流向的較低位置的資訊都已經計算完畢。直接讀取它所連接的較低位置的最短時間加一，最後找出 DP 陣列中的最大值即為所求。

## 解題方法思考
為什麼可以直接認定只在「葉節點」加冷卻器？因為這些節點是所有連通塊能量流動的「終點」。如果不加在這些位置，它們的能量將無處可去；所以這些葉節點是「必須」加冷卻器的地方。又因為題目限制「有連通路徑的節點不能同時擁有冷卻器」，而在終點加上冷卻器後，其他位置必然有路徑能流向這些終點，因此同一連通塊上也無法（也不需要）再放置其他冷卻器。

在 DP 的處理上，利用「依數值由低到高排序」來代替傳統的拓撲排序，是一個非常直觀的做法。這樣可以完美保證在處理任何一個節點時，其所需的子問題資訊（較低節點的時間）都已經計算完成，順利推導出到達冷卻器的最短時間。

## 複雜度分析
時間複雜度：建圖需要遍歷整個 N x N 網格並檢查 4 個方向，花費 O(N^2)；將節點依照數值大小排序花費 O(N^2 log(N^2))；最後 DP 陣列狀態轉移遍歷花費 O(N^2)。整體時間複雜度為 O(N^2 log N)，對於 N < 500 的限制來說足以快速通過。

空間複雜度：儲存二維網格、圖的相鄰串列（ship）、一維節點陣列（cells）以及 DP 陣列，皆需要 O(N^2) 的空間，整體空間複雜度為 O(N^2)。

## 學習心得
這次的練習讓我體會到，很多時候困難的不是演算法本身，而是如何把題目敘述剝絲抽繭。實作上雖然只是基礎的圖論建圖、拓撲排序概念與 DP，但能想到將現實情境對應到「葉節點找尋」與「值排序 DP」，才是解開這類包裝題目的關鍵，這對提升演算法思維的靈活度有很大的幫助。
