# Almost Union-Find

## 題目敘述

有 (N) 個編號為 (1) 到 (N) 的元素，初始時每個元素各自形成一個集合。

需要支援三種操作：

1. 將元素 (P) 與元素 (Q) 所在的兩個集合合併。

2. 將元素 (P) 從目前所在集合移除，並加入元素 (Q) 所在的集合。

3. 查詢元素 (P) 所在集合的元素數量以及所有元素編號的總和。

## 輸入格式

輸入包含多筆測試資料，直到 EOF。

每筆測試資料：

第一行包含兩個整數 (N,M)，分別表示元素數量與操作次數。

接下來 (M) 行，每行為以下三種操作之一：

1 P Q：合併 (P) 與元素 (Q) 所在的集合。

2 P Q：將元素 (P) 移至元素 (Q) 所在的集合。

3 P：查詢 (P) 所在集合的資訊。

## 資料範圍

(1 \le N,M \le 100000)

(1 \le P,Q \le N)

## 輸出格式

對每一個第三種操作，輸出兩個整數，分別表示 (P) 所在集合的元素數量與元素編號總和。

## 範例輸入 #1

5 7
1 1 2
2 3 4
1 3 5
3 4
2 4 1
3 4
3 3

## 範例輸出 #1

3 12
3 7
2 8

# Almost Union-Find

## 題目想法

這一題其實我寫了很久，因為它除了要求我要用 DSU 的 find 以及 union 以外，它還額外要求 escape，以及編號的總和。

一開始我想到的是正常的 DSU，但是如果用正常的 DSU，要把一個人從原本的集合移動到另一個集合會很難執行。因為 DSU 的結構本身就是透過父節點連接起來的，如果直接把某個人從中間拔出來，很容易影響到原本的結構。

我也有想過用類似指標的方式，或是類似回傳資訊的方式來處理，但是這樣不是 union 很難操作，就是沒有辦法進行路徑壓縮，最後可能會因為效率問題導致 TLE。

直到後來我去查了資料，才發現原來這一題可以使用一種空殼的方式，再加上記錄某個人現在具體在哪一個房間的概念，就能夠解出這一道題目。

在這裡我用 ROOM 記錄每個房間的父親房間，而用 NOWPLACE 代表每個人目前在哪一個房間裡面，然後用 SUMM 以及 SIZE 記錄集合的大小以及編號的總和。

## 解題過程

一開始我先讓每一個人都有一個自己的房間，所以一開始人的編號和房間編號是一樣的。

在 ROOM 裡面，我記錄每個房間的父親房間，這樣就可以把這些房間當成 DSU 的節點。

NOWPLACE 則是用來記錄每個人目前所在的房間。

這裡有一個我覺得很重要的地方，就是在 find 裡面的參數 x，我輸入進去的會是某一個人具體所在的房間，而不是這個人的編號。

因為在這一題裡面，這個人的編號和這個人所在的房間並不畫上等號，因為會有留下空殼的操作。

在 find 裡面，我用遞迴的方式一直往上找它的最高房間，代表這個集合的代表數值。

同時在回傳的時候進行路徑壓縮，讓之後再次尋找同一個集合時可以更快找到代表。

在 unite 裡面，我先找到兩個人的集合代表數值。

如果兩個人本來就在同一個集合的話，就直接不進行接下來的操作。

如果是不同的集合，就更新這兩個集合的 SIZE 和 SUMM，然後合併整個集合。

因為 DSU 的習慣，我會額外判斷讓小的集合接在大的集合後面，這樣可以讓 DSU 的樹維持比較好的結構。

在 escape 裡面，一樣是先找到兩個人的集合代表數值。

如果兩個人已經在同一個集合裡面的話，就不要做接下來的操作。

如果是在不同的集合，我就建立一個新的房間，讓要逃脫的那個人來到新的房間裡面，然後再把這一個新的房間接到新的集合裡面。

原本的房間則還是會繼續往上連接，所以不需要真的把這個人從原本的 DSU 結構裡面拔出來。

這時候只要更新原本集合和新的集合的 SIZE 以及 SUMM 就行了。

在 main 裡面，對於每一次輸入，我只需要在初始化完畢之後，依照題目所輸入的指令做出相應的行為，並且在輸入指令 3 的時候找到 P 所在集合的代表，再輸出這個集合的大小以及編號總和。

## 解題方法思考

這一題讓我覺得最精妙的地方，就是不需要真的去移動 DSU 裡面的節點。

如果直接想要把一個人從原本的 DSU 集合拔出來，就會遇到很多問題，因為他的父節點可能還有其他節點連著，直接修改很容易破壞原本的 DSU 結構。

但是使用空殼房間之後，就完全不需要處理這個問題。

我不需要知道這個集合的最高的那個人是誰，也不需要為他找一個新的最高的人，只需要建立一個空間，然後讓最高的那個人自己跑過去就行了。

而且就算是在中間的那個人，也能夠很輕易地直接 ESCAPE 到其他的集合。

我覺得這個方法最重要的地方，就是把人的編號和 DSU 的節點分開處理。

人的位置由 NOWPLACE 記錄，而真正參與 DSU 結構的是房間。這樣就可以讓人的移動不會直接破壞 DSU 的結構，同時又能繼續使用路徑壓縮。

## 複雜度分析

時間複雜度：

O((N + M) α(N))

因為使用了路徑壓縮以及 Union by Size，所以每次 DSU 操作的攤銷時間非常接近 O(1)。每次 ESCAPE 最多只會建立一個新的房間，因此整體操作可以在題目的資料範圍內有效率地執行。

空間複雜度：

O(N + M)

一開始有 N 個房間，而每一次 ESCAPE 最多會再建立一個新的房間，因此最多會使用 N + M 個房間。

## 學習心得

這一題讓我花了滿久的時間，也讓我更深入理解 DSU 到底適合處理什麼，以及哪些操作不能直接套用普通的 DSU。

以前我比較容易想到的是直接把節點接來接去，但是這一題讓我發現，如果題目要求集合裡面的元素可以移動，就不能只把人的編號直接當成 DSU 的節點。

我後來理解到使用空殼房間之後，整個問題就變得簡單很多。人的位置可以獨立記錄，而 DSU 只需要負責管理房間之間的關係。

我覺得這一題對我最大的收穫，就是讓我知道有時候遇到一個資料結構很難直接完成的操作時，不一定要一直想辦法修改原本的結構，也可以想辦法在結構外面多加一層資訊，把原本很難處理的操作轉換成比較容易處理的形式。

這一題也讓我第一次比較明顯地感受到，資料結構的精妙之處不一定是在於怎麼操作原本的東西，而是可以重新設計資料的表示方式，讓原本困難的操作變得容易。
