# 最大田地面積
## 題目想法
看完這一題後，我的核心想法是先進行資料的預處理：找出每個網格位置向右最多可以延伸出多長的「肥沃土地」。當我們知道每一格往右的連續長度後，問題就轉化為在這些長度中尋找一個連續的垂直區間，使得「區間高度與區間內最短延伸長度的乘積」最大化，進而求出最大矩形面積。
## 解題過程
 * 預處理延伸長度（get_ans 函式）：針對每一個橫列 (row)，由後往前（運用後綴的概念）進行遍歷。如果當前土地是肥沃的，就根據右邊一格的狀態進行累加，這樣就能求出每個位置往右最多能延伸的寬度，並儲存在 DP 陣列中。
 * 尋找最大面積（func 函式）：處理完水平寬度後，接著對每一個直行 (column) 呼叫 func 來計算面積。
 * 區間枚舉：因為題目限制的列數 M 很小 (M <= 200)，在 func 裡面，我直接使用兩層迴圈 O(M^2) 的方式來固定垂直區間的上邊界與下邊界。在往下延伸的過程中，隨時維護該區間內的最小寬度，並將其與當前的高度 (lon) 相乘，隨時更新最大面積 (ans)。
## 解題方法思考
這個解法的巧妙之處在於將複雜的二維矩形問題，拆解成一維的連續區間問題。先用動態規劃的思維處理好水平方向的連續長度，接著利用題目 M <= 200 的數據範圍特性，果斷選擇直接枚舉垂直方向的上下邊界。這樣設計不僅邏輯直觀，實作上也很清晰且不易產生 Bug。
## 複雜度分析
### 時間複雜度：預處理 DP 陣列需要 O(M * N) 的時間。接著對每一列執行 func 函式，每次 func 內有兩層迴圈花費 O(M^2) 的時間，共執行 N 次。因此總時間複雜度約為 O(N * M^2)。在 M, N <= 200 的情況下，運算次數約為 8,000,000 次，可以輕鬆通過時間限制。
### 空間複雜度：使用了兩個二維陣列（grid 與 dp）來儲存地圖與預處理狀態，空間複雜度為 O(M * N)，完全符合記憶體的限制範圍。
## 學習心得
透過這題，我練習到了如何利用「後綴」的技巧來預先處理狀態，並成功將二維平面的尋找問題進行降維。同時也深刻體會到，在解題時先觀察數據範圍是非常重要的一環；因為注意到 M 很小，讓我能放心地使用 O(M^2) 的迴圈枚舉，而不需要去實作如單調堆疊 (Monotonic Stack) 等較複雜的資料結構。整體來說，這是一次將 DP 預處理與暴力枚舉完美結合的優良練習。
