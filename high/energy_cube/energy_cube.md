# 能量方塊
## 題目意思
星際指揮官想要在太空站的儀表板上配置一排共 m 個能量方塊。經過篩選，指揮官選出了 n 種不同屬性的能量方塊，並從 1 到 n 進行編號。
為了確保系統穩定，規定第 i 種能量方塊的數量不能超過 a_i 個。同時，在配置時，同一種屬性的能量方塊必須連續放在一起，並且不同屬性的能量方塊需要嚴格按照編號從小到大的順序依次排列。
請計算出，總共有多少種不同的配置方案。
## 輸入格式
第一行包含兩個正整數 n 和 m，中間用一個空格隔開。
第二行有 n 個非負整數，每兩個整數之間用一個空格隔開，依次表示每一種能量方塊的數量上限 a_1, a_2, ..., a_n。
## 輸出格式
輸出只有一行包含一個整數，表示有多少種配置方案。因為方案數可能很大，請將結果對 1000007 取模後輸出。
## 範圍限制

 * 0 < n <= 100，
 * 0 < m <= 100，
 * 0 <= a_i <= 100。

# 能量方塊
## 題目想法
這一題是一道經典的動態規劃（DP）求組合方案數的問題。因為我對動態規劃的掌握度還需要加強，所以最近開始針對這類題目進行特訓。這題的核心概念在於計算：「當我只使用前 i 種物品，且要湊出總數為 j 的情況下，總共有多少種方法數？」
## 解題過程
具體來說，當我們從「只考慮前 i 種能量方塊」推進到「考慮前 i+1 種能量方塊」時，就等於新增了一種能量方塊可以選擇。假設這新增的方塊最多可以拿 a_i 個，我們就可以嘗試拿 k 個（其中 0 <= k <= a_i）。
因此，當前總數為 j 的方法數，就會是加上前一次狀態（前 i 種）總數為 j-k 的所有方法數的總和。我們只需要嘗試 0 到 k 個的各種可能性，把所有合法對應的方法數加總，就能推導出當前的答案。這是一個動態規劃中非常有代表性的轉移邏輯。
## 解題方法思考
實作上我寫了兩個版本來優化空間：
 * 二維陣列（滾動陣列）：因為在更新當前狀態時，只會用到上一次（也就是上一列）的資訊，最直觀的做法就是開兩個一維陣列交替使用，這樣就能大幅節省空間。
 * 一維陣列（空間極致優化）：為了進一步把陣列縮減成一個，我觀察到狀態轉移時，當前的 j 永遠只會依賴上一個狀態中「小於或等於 j」的資訊。因此，只要把迴圈改成「由大到小」倒過來遍歷 j，就能確保在讀取 j-k 狀態時，拿到的還是上一輪的舊資訊，不會被提早覆蓋掉。這樣就不需要開兩個陣列了。
## 複雜度分析
### 時間複雜度：
O(n * m * a_i)，其中 n 是能量方塊種類數，m 是要配置的總數，a_i 是每種方塊的數量上限。最差情況約為 100 * 100 * 100 = 1,000,000 次運算，在時間限制內可以非常快速地執行完畢。
### 空間複雜度：
第一種滾動陣列寫法為 O(2 * m)，第二種一維陣列寫法成功降維至 O(m)，兩種做法皆十分優秀且節省記憶體。
## 學習心得
雖然這是動態規劃中非常經典的一種作法（類似背包問題的變形），但因為一開始對這種思考模式還不太熟悉，所以卡了滿久的時間。不過在徹底解決這題，並實際比較了兩種空間優化的程式碼後，感覺對這類動態規劃的狀態定義與轉移方式有了相當深度的了解，收穫非常大！
