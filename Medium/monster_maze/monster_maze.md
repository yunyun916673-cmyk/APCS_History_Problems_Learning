# 魔王迷宮

## 題目敘述

有一個 n × m 的棋盤，上面有 k 個魔王。每個魔王都有自己的初始位置與固定的移動方式。

每一回合，所有魔王會同時進行移動。魔王會先在目前所在的位置留下炸彈，再按照自己的移動方式前進。

如果魔王移動到棋盤外，就會消失；如果移動到已經有炸彈的位置，則會被炸死，而該位置的炸彈也會被引爆。

由於所有魔王是同時移動，因此必須以同一回合的狀態判斷所有魔王的移動結果。

當所有魔王都消失後，請計算棋盤上最後仍存在的炸彈位置數量。

## 輸入格式

第一行輸入三個整數 n、m、k，分別代表棋盤的大小與魔王數量。

接下來 k 行，每行輸入四個整數 r、c、x、y，表示一個魔王的初始位置為 (r, c)，之後每回合會依照固定的移動方式前進。

## 輸出格式

輸出所有魔王消失後，棋盤上仍存在的炸彈位置數量。

範例輸入 #1

1 6 3 0 0 0 0 0 2 0 -1 0 4 0 2

範例輸出 #1

4

範例輸入 #2

5 5 2 0 0 3 2 0 0 2 3

範例輸出 #2

3

# 魔王迷宮

## 題目想法

一開始看到這題的時候，我覺得它主要就是一題模擬題。我需要模擬每一個怪物的移動，並且記錄最後還留在棋盤上的炸彈。

不過這題我其實做了兩次，因為我第一次寫的時候少注意到一個很重要的條件，就是每一個怪物會同時移動。

我第一次直接在 BFS 裡面讓怪物一個一個移動，這樣就會產生問題。例如某一個怪物先移動到位置甲，而位置甲剛好有另一個怪物，但是另一個怪物還沒有移動。這樣如果直接在當下判斷，就可能讓先到達位置甲的怪物沒有被判定爆炸。

所以後來我重新思考這題的移動方式，發現不能讓怪物一個一個處理，而是要把每一回合當成一個完整的階段，讓所有怪物先同時完成移動，再一起判斷結果。

因此我最後使用 BFS 分層的方式，利用每一層代表一個回合。

## 解題過程

首先讀入 N、M、K，分別代表棋盤大小以及怪物數量。

我不需要把整張棋盤完整存下來，因為我只需要知道每個位置現在有沒有炸彈，所以使用 "isbomb" 來記錄棋盤上的炸彈。

接著使用 "steps" 儲存每一個怪物每次移動的方向，其中 S 和 T 分別代表列與欄的移動量。

再使用 "pork" 儲存每一個怪物目前的位置。

最後使用 "temp" 作為 BFS 的 queue，裡面存放目前還活著的怪物編號。

初始化完成後，我另外建立 "dies"，用來暫時儲存被怪物踩到、需要被消耗掉的炸彈位置。

進入 BFS 後，我先取得目前這一層的怪物數量，代表這一回合需要同時處理多少隻怪物。

接著讓這一回合的每一個怪物都在原本的位置留下炸彈，然後向自己的方向移動一步。

這裡不能移動一隻就立刻判斷，而是要先讓這一回合所有怪物都完成移動，才能保證符合題目中的同時移動。

所有怪物移動完成後，再逐一檢查牠們現在的位置。

如果怪物已經離開棋盤，就直接判定死亡。

如果怪物現在的位置有炸彈，也代表牠踩到炸彈，所以判定死亡，並把這個炸彈的位置存進 "dies"。

如果沒有出界，也沒有踩到炸彈，就代表這隻怪物還活著，把牠重新放進 BFS 的 queue 中，等待下一回合。

等所有怪物都判斷完成後，再遍歷 "dies"，把這些已經被踩到的炸彈從 "isbomb" 中設為 "false"。

最後清空 "dies"，開始下一回合。

這樣就可以確保同一回合中的所有怪物都是同步處理的。

我原本第一次實作時，就是因為沒有注意到這個同時移動的條件，所以直接讓怪物一個一個移動，最後才發現這樣會產生順序上的問題。修改成 BFS 分層後，每一層就是一個完整的移動回合，就可以解決這個問題。

## 解題方法思考

這題本身其實算是一套標準的模擬題目，再加上一個比較容易忽略的小陷阱。

如果沒有仔細看題目的話，很容易直接想到讓怪物一個一個移動，但這樣會受到怪物處理順序影響。

後來我想到可以使用 BFS 分層，讓每一層代表一次移動。這樣我就可以先讓所有怪物完成這一回合的移動，再統一判斷牠們是否死亡，就不會因為處理順序不同而產生錯誤。

在資料結構方面，我不需要建立完整的棋盤資訊，只需要知道某個位置現在是否有炸彈，因此使用布林值的 "isbomb" 就可以完成。

另外，我使用 "pork" 記錄怪物的位置，使用 "steps" 記錄每個怪物的移動方式，再利用 queue 管理目前還活著的怪物。

這樣的資料結構剛好對應到題目需要維護的資訊，也不需要額外儲存不必要的資料。

## 複雜度分析

### 時間複雜度：

每一回合需要遍歷目前的怪物，因此單回合大約是 O(K)。

假設模擬 T 回合，整體時間複雜度為 O(KT)。

我當時另外估計，如果非常極端地假設所有怪物可以一直走，並且共同把整個 N × M 的棋盤都走過一次，那麼每一回合有 K 個怪物移動，估計大約需要 N × M / K 次動作才能把整個棋盤走過。

雖然這個情況實際上不太可能真的發生，但用來估計這題的模擬量級已經足夠，而且在題目的限制下非常小，因此直接模擬不會有時間問題。

### 空間複雜度：

"isbomb" 需要儲存整個棋盤，因此是 O(NM)。

"steps"、"pork" 和 BFS queue 都最多儲存 K 個怪物，因此是 O(K)。

所以總空間複雜度為 O(NM + K)。

## 學習心得

這題讓我印象最深的不是模擬本身，而是我第一次實作時犯的錯誤。

我第一次看到題目時，直接想到用 BFS 讓怪物一個一個移動，但是後來才發現題目要求所有怪物同時移動。如果沒有注意到這個條件，就算整個模擬流程看起來都合理，最後還是會因為怪物的處理順序不同而得到錯誤答案。

後來我把問題改成分層 BFS，每一層代表一個回合，先讓所有怪物完成移動，再一起判斷結果。這讓我了解到，模擬題不一定只是把題目描述直接翻成程式而已，題目中像是同時、依序、先後這種描述其實都可能直接影響程式的執行方式。

這題也讓我更加注意題目中的細節。以前看到模擬題時，我可能會比較直接地開始寫程式，但這次的錯誤讓我知道，在真正開始實作之前，應該先確認每一個動作的時間順序，以及哪些事情需要同時發生。

最後我也發現，只要把每一回合需要維護的資訊整理清楚，這題其實就是很標準的模擬。真正困難的地方不是程式碼本身，而是第一次有沒有正確理解題目的規則。
