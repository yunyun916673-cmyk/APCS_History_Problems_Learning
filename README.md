## 一、專案動機

為了提升程式設計能力並準備 APCS 檢測，我開始整理歷屆試題的解題過程與學習紀錄。

在練習的過程中，我發現要解決一個問題，最重要的不只是寫出程式，而是分析問題、選擇合適的方法，並透過測試與修正找到更好的解法。因此，我建立了這個專案，用來記錄自己在 APCS 歷屆試題上的學習歷程。

## 二、學習目標

- **C++ 程式設計與常用語法**
- **資料結構與演算法基礎**
- **分析問題與設計解法**
- **APCS 歷屆題目練習，累積實際解題經驗**

### 🐍 Python 解法
為了替之後參加 CTF 比賽做準備，我開始學習 Python 的各種語法與應用，並逐漸將其熟悉、內化為自己的工具，因此也補上部分題目的 Python 解法。其中 Python 檔案中的解法，都是我重新實作並重新思考後得到的結果，會包含我重新思考題目後產生的新想法。

## 三、學習方法

每完成一道題目，會整理出以下內容：
1. **題目的核心問題**
2. **解題思考過程**
3. **使用的資料結構與演算法**
4. **程式實作方式**
5. **遇到的錯誤與改進方法**

藉由整理解題紀錄，回顧自己在思考方式上的改變，了解哪些地方需要加強。

## 四、專案整理方式

依照題目難度進行分類：
* **簡單題**：基本語法與基礎解題技巧
* **中等題**：常見演算法與資料結構應用
* **中高難度題**：較複雜的思考與優化
* **困難題**：進階演算法與解題策略

每一道題目皆包含程式碼以及個人的解題紀錄。

有些題目可能不是APCS的歷屆試題,但是仍然是我在準備APCS的過程中去練習的題目。

## 七、專案完成方式與 AI 輔助說明

為了兼顧學習的深度與紀錄的效率，本專案的每一道題目與心得紀錄，皆嚴格遵循以下流程完成，以確保所有的學習成果皆源自真實的理解與獨立思考：

1. **獨立嘗試與實作**
   面對每一道題目，我必定會先進行獨立思考，嘗試分析問題、設計演算法，並親自撰寫程式碼。
2. **尋求思路引導（拒絕直接抄寫解答）**
   若在解題過程中遇到瓶頸或卡關，我會向 AI 尋求「解題方向」或「思路提示」，而不是直接索取完整程式碼。獲得靈感後，我會回到編譯器前，再次嘗試靠自己將邏輯實作出來。
3. **邏輯校正與 AC 確認**
   完成初版程式後，若遇到 Bug 或效能瓶頸，我會與 AI 討論並進行邏輯校正，釐清自己觀念上的盲點，直到程式碼在評測系統上成功獲得 AC（Accepted）。
4. **高效率的心得產出**
   在順利解出題目後，我會將自己真實的「解題思路、遇到的困難、學到的技巧」提供給 AI，請它協助我整理成專案中統一的 Markdown 格式。
   - **核心理念**：交由 AI 排版是為了大幅節省打字與格式化的時間，讓我能將寶貴的時間與精力集中在「解題」與「思考」本身。專案中的每一行邏輯、每一段心得，皆為我本人親自實作與真實體悟，絕無造假或依賴 AI 直接生成。

透過這樣的流程，AI 扮演的是「引導助教」與「排版助手」的角色，而核心的知識吸收與程式實作，依然 100% 由我自己完成。
